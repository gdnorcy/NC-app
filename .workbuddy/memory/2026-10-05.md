## 日期/时间组件小程序端不弹选择器（用户真机反馈）✅ 已修
- **根因**：`SuperFormRender.vue` 的日期/时间用 `<input type="date"/"time">` —— 这是 **H5 专属属性**，
  **小程序端 input 不支持、不弹选择器**。H5 原生 input 支持所以 H5 一直正常 → **只在 H5 验证会漏掉小程序端**。
- **修**：全部改 uni `<picker>`（复用 select 组件既有范式，两端一致、无需条件编译）：
  时间点→`mode="time"`；时间段→双 picker+`~`；单个日期→`mode="date"`；日期范围→双 picker+`~`；
  支付「参与日期」同样改 picker（共 7 处）。新增 `onDateTimePick(id, ev, part)`：
  part 空=单值写 `values[id]`，part=start/end 复用 `setRangePart` 写 '起~止'。值格式/校验正则不变。
- 面板只提供 time/timerange/date/range（**无 datetime**）→ `timeType()` 的 datetime 分支本就不可达，删死函数。
- **验证**：SFC 编译 OK；72 测试通过；H5 实测渲染为 `uni-picker`（请选择日期/请选择时间）；
  小程序重建后产物 4×mode=date + 3×mode=time、0 残留 type=date/time、2.4M。
- 🔴 **教训（跨端必查）**：`input type=date|time|datetime-local` 是 H5-only；小程序端任何"选择器"都要
  `<picker mode=date|time|selector>`。**C 端组件改动必须在 H5 与小程序两端都验**（此前只验 H5 是漏检根因）。
- ⚠️ gen-mp-sicons 耗时 ~4min（渲染 482 PNG 后清理）。若 `src/utils/sicons-base64.js` 已完整且 SIcon.svgMap
  未变，**可跳过该步**（uni build 会直接打包已有 base64），大幅加快重建。

## 九轮：宫格图标「孔洞糊死」真因 = currentColor 黑色回退（不是描边粗）

### 现象
开发者工具里 9 宫格图标「和之前不一样，变得很难看」：
- `apps` 九宫点：9 个白点中心带黑洞
- `radar` 同心圆：中心点黑洞
- `dynamic` 气泡：3 个气泡点黑洞

### 走过的弯路（重要教训）
第一反应误判为「描边随显示尺寸等比放大 → 描边 3.58px > 内部间隙 4.3px → 糊死」，
为此实现了一整套 `strokeWidth` prop + 自适应描边（43px → 1.3）+ 生成脚本白色描边变体
（509 条 base64，主包 1441 → 1462KB），跑了两轮 4 分钟构建。
**结果：实心点完全没变化** —— 因为那些点根本不是描边出来的。

### 真因
源码里这些点写的是 `fill="currentColor"`：
```js
apps:    '<circle cx="6"  cy="6"  r="1.8" fill="currentColor"/>'  × 9
radar:   '...<circle cx="12" cy="12" r="1.4" fill="currentColor"/>'
dynamic: '...<circle cx="8.2" cy="11.5" r="0.9" fill="currentColor"/>' × 3
wallet / storage / wechat 也用了（共 6 个图标）
```
生成的根 SVG 是：
```
<svg ... fill="none" stroke="#ffffff" stroke-width="2">
```
`fill="currentColor"` 覆盖了父级 `fill="none"`，而 `currentColor` 取的是 CSS **`color`** 属性——
根 `<svg>` **没有声明 color** → 按 SVG 规范回退到**黑色**。
所以白描边图标上出现黑点，视觉上正好是「孔洞糊死」。

### 修复（1 行 × 2 处）
根 `<svg>` 补上 `color` 属性，让 `currentColor` 正确继承描边色：
- `web-app/src/components/SIcon.vue` → `buildSvgDataUri()`（H5 侧 data URI）
- `web-app/scripts/gen-mp-sicons.js` → 渲染循环里的 SVG 模板（小程序侧 PNG）
```diff
- fill="none" stroke="#${hex}" stroke-width="2"
+ fill="none" color="#${hex}" stroke="#${hex}" stroke-width="2"
```

### 已回滚的无效改动
- `SIcon.vue` 的 `strokeWidth` prop —— 删掉
- `home.vue` 的 `gridIconStroke()` + `:stroke-width` 绑定 —— `git checkout` 还原
- `gen-mp-sicons.js` 3.6 节描边变体（walkStroke / GRID_STROKE / pairs 派生）—— 删掉
- key 解析恢复为 `lastIndexOf('-')` 简单切分

### 判定依据（下次直接用）
- **描边图标**（crown / dist / card / market…）：`stroke-width` 有效，粗细影响观感
- **实心点图标**（apps / dynamic / radar 中心点）：靠 `fill`，**`stroke-width` 完全无效**
- 看到「点/孔洞糊成一坨」先查源码是 `fill=` 还是纯path，不要先动 stroke-width

### 其他环境坑（复用）
- **产物 `sicons-base64.js` 里是裸 base64**（`data:` 前缀运行时拼），校验正则若要求
  `"...(data:image/png;base64,...)"` 会全部 MISS，误判成「变体没落地」
- **sharp 报错 `Input buffer has corrupt header` = SVG 文本里有裸 `<`/`>`/`&`**，
  拼 `<text>` 标签必须先 `&amp; &lt; &gt;` 转义
- **sharp composite 报 `expected integer ... top but received 874.8`** → 坐标要 `Math.round`
- **sharp 路径**在仓库根 `node_modules`，不在 `web-app/node_modules`
- **node 脚本含top-level await 时不能混require** → 包 `(async()=>{...})()`
- **Grep 工具在中文路径下静默失效**（返回空但内容存在）→ 必须用 node fs 逐行复核

## 十四轮：设计器画布白屏（TDZ）+ 底部菜单图标不居中 + 按钮底色误配

### 🔴 问题 3「改了列数/底色，预览区没变化」= PageEditor 整个组件崩溃白屏

**真因不是 `columns` 或 `bg` 的存取问题，而是 JS 运行时异常**：

[Vue warn]: Unhandled error during execution of watcher getter  at <PageEditor>

`PageEditor.vue` 里 `watch(() => selectedComp.value?.props, ...)` 写在文件前部（`onMounted` 之前），

`watch` 会**立即执行 getter** 拿到 `selectedComp.value`，此刻该`const` 还在 `<script setup>` 的
**TDZ（暂时性死区）** → 抛 ReferenceError → setup 阶段失败 → **整个设计器白屏**（`#app` innerHTML 长度 0）。
`7ca9b73`（悬浮组件工具条跟随）引入。

- **修**：把两个 watch（`watch(selected,...)` 与 `watch(() => selectedComp.value?.props,...)`）

- ⚠️ **`watch` / `computed` / `onMounted` 里引用 `const` 声明的 ref，必须写在那个 ref 声明之后**。
  只扫这一类（`const xxx = ref(...)`）——`function` 声明会提升，不受影响。

### 问题 2：底部菜单图标不居中 —— `margin:0 auto` 对小程序原生`<image>` 不可靠

## 十五轮：按钮「不能单独设置组件背景色」= bgColor 被上两次色 + 两端实现漂移

### 用户诉求
「这个按钮还是不能单独设置组件的背景色呀」——指后台改按钮的「背景色」时，
分不清/改不动是**按钮自身底色**还是**组件容器背景**。

### 根因 ①：同一个 `bgColor` 被上了两次色（主因）
`containerStyle(c)` 给**外层容器 `.dp-item`** 上 `p.bgColor` + `p.radius`，
而组件自身的 `dpBtnStyle(p)` 又消费同一个 `p.bgColor` + `p.radius`
→ 改一个字段，**容器和自身两层一起变**，无法单独设置。
视觉副产物：`marginLR`/`padding` 有值时四周多出一圈同色边框，
且容器圆角与自身圆角错位。

**修法（引入 `HIDDEN_BG_TYPES`）**：自身根节点就是色块的类型，
容器不再上背景色与圆角，只保留 padding / 外边距。
- 判据：**该类型根节点是否消费 `p.bgColor`**。
  子元素里的彩色按钮（goods-* 的 `buyBtnBg`、channel-* 的 `btnBg`、表单的 `btnColor`）**不算**。
  我第一版把 `goods-all` / `channel-profile` 误加进表，单测立刻报错纠正（channel-profile 根节点
  确实是模板内联 `background: c.props.bgColor`）。
- 表里也放 `containerStyle` 的 `borderRadius` 一起排除：`dpBtnStyle` 第一行自带
  `borderRadius: (p.radius ?? 8)`，不会因容器不给圆角而丢失（单测已锁）。

### 根因 ②：admin 画布根本没绑容器样式（跨端漂移）
`PageEditor.vue` 的 `.pe-comp` 完全不绑 background / borderRadius
→ **同一个组件在画布里看不到容器底色、真机却有一层**。这正是「改不动/分不清」的直接体感。

### ② 底部菜单图标不居中（真因：**CSS 穿不透小程序自定义组件**）

前两轮我都在 `CardTabBar.vue` 加 `.mtb :deep(.s-icon){...}`，**全是无效功**。
产物实证（一眼看出）：

```
WXSS: .mtb.data-v-70ba87a9 .s-icon{...}      ← 后代选择器
WXML: <s-icon class="data-v-70ba87a9" .../>   ← 直接子元素 + 独立样式作用域
```

两条都对不上，**双重失效**：
1. `:deep()` 编译成**后代选择器**，要求 `.s-icon` 是后代；而 `<SIcon>` 是**直接子元素**
2. 更关键：小程序自定义组件**样式作用域隔离**，父组件 wxss 的 `.s-icon` / `:deep(.s-icon)`
   **都跨不过组件边界**

**修法：内联 style 是唯一能穿透小程序组件边界的手段。**
给 `SIcon` 加 `block` prop，由组件自己出内联
`display:block;margin:0;align-self:center;flex:none`。
产物已确认编译为内联 `alignSelf:"center",flex:"none"`。

**配套：需要给子组件加class 时，用「模板显式加 class + 父组件直接选该class」**，
不要写 `:deep()` 后代选择器。依据：`SIcon` 未设 `inheritAttrs:false`，
Vue 会把父传 class 合并到根节点（产物 WXML 可见 `class="data-v-xxx"`），**跨端通用**。
例：slider 态的 `top:-24rpx` 改选 `.mtb-icon`。
