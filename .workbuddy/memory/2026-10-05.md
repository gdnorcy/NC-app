## 日期/时间组件小程序端不弹选择器（用户真机反馈）✅ 已修
- **根因**：`SuperFormRender.vue` 的日期/时间用 `<input type="date"/"time">` —— 这是 **H5 专属属性**，
  **小程序端 input 不支持、不弹选择器**。H5 原生 input 支持所以 H5 一直正常 → **只在 H5 验证会漏掉小程序端**。
- **修**：全部改 uni `<picker>`（复用 select 组件既有范式，两端一致、无需条件编译）：
  时间点→`mode="time"`；时间段→双 picker+`~`；单个日期→`mode="date"`；日期范围→双 picker+`~`；
  支付「参与日期」同样改 picker（共 7 处）。新增 `onDateTimePick(id, ev, part)`：
  part 空=单值写 `values[id]`，part=start/end 复用 `setRangePart` 写 '起~止'。值格式/校验正则不变。
- 面板只提供 time/timerange/date/range（**无 datetime**）→ `timeType()` 的 datetime 分支本就不可达，删死函数。
- **验证**：SFC 编译 OK；72 测试通过；H5 实测渲染为 `uni-picker`（请选择日期/请选择时间）；
  小程序重建后产物 4×mode=date + 3×mode=time、0 残留 type=date/time、2.4M。
- 🔴 **教训（跨端必查）**：`input type=date|time|datetime-local` 是 H5-only；小程序端任何"选择器"都要
  `<picker mode=date|time|selector>`。**C 端组件改动必须在 H5 与小程序两端都验**（此前只验 H5 是漏检根因）。
- ⚠️ gen-mp-sicons 耗时 ~4min（渲染 482 PNG 后清理）。若 `src/utils/sicons-base64.js` 已完整且 SIcon.svgMap
  未变，**可跳过该步**（uni build 会直接打包已有 base64），大幅加快重建。

  但绝大多数页面既没自绘导航也没状态栏占位 → 标题看不到 + 内容被胶囊压住。
- **「与最小化/三个点重叠」根因**：胶囊是微信原生控件，**不可覆盖、点击会冲突**，
  官方设计指南明确要求「预留该区域空间」。各页各写一套导航（mall-nav/msg-nav/nav-bar/
  owner-nav/sk-nav/ph-topbar/page-bar 共 7 套），**全部无 statusBarHeight 占位与胶囊避让**；
  部分页用 `padding:88rpx 32rpx 0` **硬编码假状态栏**（刘海机~44px、非刘海~20px，一头高一头低）。
