## 超级表单「左右布局排版错乱 + 样式设置改了没反应」修复
- 用户实测（截图）：切到左右布局后预览排版乱飞 + 样式设置"还是用不了"。两个独立根因：
  1. **排版乱**：设计器预览 DOM 是 `.sf-comp-wrap`，旧 CSS 的 `.sf-form.horizontal .sf-field{flex:1 1 45%}` 在设计器里**选择器根本匹配不上** → 组件宽度失控；且 flex-wrap 默认 `align-content:stretch` 把行距拉满屏；`.sf-canvas` 没有 `align-items:flex-start`，手机壳被拉到 ~1000px。
  2. **样式没反应**：组件圆角/输入框圆角/组件左右边距/标题字号/输入字号/框线风格**没有任何消费方**，改了当然看不到变化。
- **修复方案（CSS 变量三级覆盖链）**：`.sf-phone-body` 下发 `--g-radius`/`--g-input-radius` → `.sf-comp-wrap` 逐组件下发 `--c-input-radius`(=comp.style.radius，否则回落 g)/`--c-title-size`/`--c-input-size` + padding=comp.style.marginX → ComponentPreview 与 C 端 fill.vue 的输入/盒模型消费这些变量。线风格=`.cs-line` class（去边框留底线，`:deep()` 穿透子组件 scoped）。C 端 `fieldStyle` 由全局 computed 改为逐组件函数。
- 设计器横向布局补 `.sf-phone-body.horizontal .sf-comp-wrap{flex:1 1 45%}` + `align-content/align-items:flex-start`。
- **验证（headless 量测）**：上下布局相邻 top 差 [94,94,112,112]；左右布局 tops 两两成对、widths 173×4（≈半宽）+360（末行独占，flex 正常行为）；computed 命中 `--g-input-radius:3px/--c-title-size:16px/输入框圆角3px/padding 10px`；手机壳高度回 640。截图确认左右布局为整齐两列。
- **教训**：做"预览=产物"时，预览容器与 C 端的 DOM 结构不同，CSS 选择器不能照搬；样式设置类功能必须让消费端真的读值，否则"能用"是假象。样式下发统一走 CSS 变量链（全局→组件级覆盖），设计器与 C 端两份 CSS 各自消费同一套变量名。
