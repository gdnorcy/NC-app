## 按钮「没有居中」——作废上一轮的负 margin 方案（用户第二次反馈）
上一轮 `28e7095` 的解耦实现**本身是错的**：用 `marginLeft:-LR` + `width:calc(100% + 2*LR)` 让按钮溢出抵消容器边距。
🔴 **该方案只在容器无 padding 时成立**；本项目容器有 `MIN_BG_PADDING=8` → 按钮**盖住容器底色并溢出容器**，视觉上比满行更宽且偏左；且 `pct<100` 时宽度被收窄却仍带负 margin → 双偏。
正确解法：**百分比宽度 + `margin:0 auto`**。百分比参照容器内容宽，容器 marginLR 左右对称 → 容器中心==页面中心 → auto 边距即居中；按钮大小只由 `widthPercent` 决定，与容器边距无关。
- 整行：`width:pct%` + `margin:0 auto`
- 自适应：`display:block` + `width:fit-content` + `margin:0 auto`
  🔴 两个实测坑：① `inline-block` 的 `margin:auto` **不居中**（两侧 auto 被当 0）—— 这正是用户看到的现象；② 改 `block` 后 `width:auto` 又**撑满**容器 → 唯一正解是配`fit-content`。

🔧 **本轮最大教训：单测全绿 ≠ 视觉正确。** 我第一版改动 9 例单测全过、真机却偏左。
CSS 几何问题必须**像素实测**：写独立 HTML 复刻真实结构（容器 padding/背景色/有无 `text-align` 全还原），无头 Chrome 截图肉眼看 or `getBoundingClientRect()` 打印。
⚠️ 无头 Chrome `--dump-dom` 读 `<pre>` 多次拿到空内容（脚本时序早于虚拟时间耗尽）→ **优先 `--screenshot`**。
实测五场景：A(LR=0,100%) 与 B(LR=20,100%) 净宽相等 → 解耦成立；C(50%)/D(LR=40,50%) 居中；E(自适应) 内容宽且居中。
单测新增 3 条回归锁：不得出现 `calc`/负 margin、auto 必须 `fit-content`、不得 `inline-block`。web-app 257 例通过；三端构建通过；MP 主包 1450KB。提交 `706ca7e`。
