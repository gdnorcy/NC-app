## MP 主题色图标全黑 bug（提交 cee0819）
- 报修：「切换主题色为草绿时，名片内容中的图标是黑色的，没有跟主题色，跟之前玫红的不同」。
- **是 bug 不是设计**：MP `<image>` 不支持 SVG data-URI → SIcon MP 分支用构建期烘焙的 base64（gen-mp-sicons → sicons-base64.js），色板=「构建那一刻」的源码静态色+DB 租户主题色，未命中兜底黑色。设计中心支持自定义取色 → 租户切主题（玫红→草绿）后运行期颜色不在烘焙表 → 全黑。H5 无此问题（SVG data-URI 吃真实色）。只烘 14 预设不够（自定义色仍坏 +150KB 爆主包）。
- 修复=回退链：**精确命中烘焙表→离线 base64（零请求）；合法 hex 未命中→服务端 `GET /api/card/sicon?name=&color=`（sharp 同管线任意色，内存 FIFO cap1000 + 24h immutable）；非 hex 脏值→黑色变体**。svgMap 单一事实来源仍读 web-app SIcon.vue（与 gen-mp-sicons 同份，禁复制）。
- 实证：库里租户主题在两次构建间被改成深蓝 #002FA4（sicons 键从 fe0137/ff5169/ffe5eb → 002fa4/1149d2/e5eaf6）——烘焙表永远滞后于 DB，这就是 bug 的活证据。端到端 curl 草绿 card → 200 PNG 72×72 调色板 (79,161,63)。
- 回归：server sicon-endpoint.test.js 8 例 + web-app siconFallback.test.js 14 例（new Function 提取 mpIconSrc computed 注入 siconsBase64/API_DOMAIN 真实执行：精确命中/草绿 URL/脏值黑/空串四路）。全量 web-app 611 / server 439（4 存量失败不变）。
- 元规则：**「小程序端图标/图片不跟主题色」先查构建期烘焙色板 vs 运行期颜色的差集**，别再改 CSS（SIcon color 是 prop 不是样式）；MP 端「任意运行期色」的正解是服务端按需渲染 + 离线烘焙做热路径。
