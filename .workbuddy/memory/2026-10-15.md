## 集市状态不一致 bug 修复（is_public vs card_market_items 两套体系）
- **病根**：C 端「公开到人脉集市」开关（displaySettings.vue + create.vue 表单同款）只写 `card_profile.is_public`（服务端仅 admin 客户列表 customer.js:953 消费），**从不建 card_market_items**；而 myCard 集市状态 / market 列表的唯一数据源是 card_market_items（/market/my-status、/market/list）→ 真机表现「开关已开、toast 已公开到集市，myCard 永远显示未上架」。两套并行体系，开关是空头支票。
- **修复模型**：开关就是集市场上架控制（文案本就承诺「可在集市页被所有人发现」），is_public 降级为可见性派生 flag。不变量：**开关为开 ⇔ 主解析主体有上架记录（或审核中）**。
- **单一来源 `web-app/src/utils/marketLink.js`**（displaySettings/create 共用，防两端漂移）：`pickPrimarySubject`（active 个体优先否则首个 active，与 myCard activeSubject 同款）、`findMarketItem`（subjectType+subjectId 双匹配）、`syncMarketWithIsPublic(api, isPublic)`（api 注入 → fake api 可单测；幂等：已一致不 toggle；no-subject=无 active 主体；soft=my-status 网络失败）。多主体只管 myCard 展示的同一个主体，不误伤 market.vue 独立管的员工主体记录。
- **displaySettings.vue**：onPublicChange 保存 is_public 后 syncMarket；无主体/硬失败（集市未开启/配额满）→ rollbackPublic 回滚 is_public，开关只说真话；soft 不回滚（下次访问自愈）；load() 跑 healMarketLink **存量自愈**（只补「开着却没上架」一个方向；无主体也回滚+说明）。manual 审核模式 → toast「已提交上架申请，等待审核」。
- **create.vue**：三条保存路径成功后 best-effort `syncMarketAfterSave(!!form.isPublic)`（延迟 1s 轻提示不打断主 toast；no-subject 静默——入驻审核中本就不能上架）。编辑态 isPublic 载入没问题（toCard 有 isPublic: !!row.is_public）。
- **服务端反向闭环 cardMarket.js `syncCardsPublic(userId, 0/1)`**：/market/toggle 增/删记录、/market/force-remove 删除时同步 is_public——否则用户在 market.vue 下架后再进展示设置页，会被 heal 复活上架。**PUT /cards/:id 保持纯可见性语义不代建 item**（联动归 C 端：带主体解析/审核态/配额语义，服务端代建会绕过）。
- **回归**：web-app `marketLinkSync.test.js` 29 例（util 直接 import + fake api 精确镜像服务端 toggle 语义「建=带 auditStatus，删=不带」+ 两页调用链正则防回退 + myCard 读取链不变）；server `market-ispublic-sync.test.js` 5 例（supertest：上架/下架/强制下架联动 is_public、PUT 边界、存量坏数据可复现+heal 后一致）。
