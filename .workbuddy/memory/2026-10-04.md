## 第 6 轮：「框内的三个风格无效。左右边距无效，也不知是调什么的」— 已闭环

**根因（两条）**
1. **三个风格无效**：`styleType` 的消费点全库只判`=== 'line'`（`SuperFormRender.vue:11`/`ComponentRender.vue:417`/`SuperFormDesigner.vue:66`）→ `box1/box2/s2/s3/slider` 全落默认分支，只有「线风格」生效。且 `ComponentPreview.vue` 根节点 `.cmpv` **原本完全不挂任何风格 class**。另外 `defaultStyle` 写死 `s.styleType='box'`，而 textarea/date/time 的 boxLine 选项是 box1/box2/line（date/time 首项还是 line）→ 默认态是个不存在的 class。

**关键设计决策：引入 `styleVariant()` 做「值→语义」收敛**
`styleType` 取值按组件各自命名，跨组件会撞名（radio 的 s1 与 filedownload 的 s1 语义不同；radio 的 s1 作用于**选项区**而非输入框）。故在 `sfComponentStyle.js` 新增单一映射函数，三端只认语义不认原始值：
| 语义 class | 含义 | 来源值 |
|---|---|---|
| `sfv-box` | 描边+浅底 | box / box1 / s1 |
| `sfv-plain` | 白底+无描边 | box2 / s2 |
| `sfv-line` | 去框仅底线 | line / s3 |
| `sfv-step` | 数字步进器 | number.step |
| `sfv-slider` | 滑块 | number.slider |
| `sfx-optbox/optplain/optline` | 选择类三态（作用在**选项区**） | radio/checkbox/select 的 s1/s2/s3 |
- 非选择类的 `s1/s2/s3`（仅 filedownload）按输入类语义分派 —— 否则两档都落`sfv-box` = 视觉相同 = 风格2 是死参数（**单测已捕获此点**）。

**顺带修掉的第二个死参数**：number 的 `slider` 此前只切 class、**从未渲染滑块**；预览的 number 也只有裸 input（与 C 端不一致）。现三端都渲染真实滑块（C 端用原生 `<slider>`，预览用 div 滑轨 + `sliderVal/sliderPct`），滑块初值口径统一为 `输入值 > prefill > min`。

**单测**：新增 2 个用例（「原始值全部映射到语义class，无死值」逐值断言+ 同类型各档必须互异、「选择类三档作用于选项区 / number 两档互斥」）→ **21/21 passed**。

## 第 9 轮：多行文本在预览端应体现为多行 + 字数统计（顺带修出一个真 bug）

用户看 C 端截图（多行文本右下角有「0/400」）指出**设计器预览没体现**。核查发现两层问题：

**问题 1（预览端结构错）**：`ComponentPreview.vue` 里 `text` 与 `textarea` **共用 `<input class="cmpv-input">`**
—— 多行文本在设计器里渲染成单行输入框，根本看不出「这是多行」。
修法：拆开，`textarea` 用真正的 `<textarea class="cmpv-input cmpv-textarea">`，
高度走 `--c-input-height`（与 C 端同源，默认 84px / 本例 166px）。

**问题 2（C 端真bug：`maxLength` 完全没生效）**
C 端 `<textarea>` **没绑 `maxlength`** → uni H5 走**内置默认上限 140**。
用户在面板设「最多输入 400」，C 端实际只能输 140 字（DOM 实测 `maxlength="140"`，配置是 400）。
你截图里显示「0/400」是**巧合**（uni 内置计数恰好也渲染成 0/140 样式，但真上限是 140）。
修法：`:maxlength="comp.content.maxLength > 0 ? comp.content.maxLength : -1"`。

**问题 3（两端计数口径不一致）**：uni H5 `<textarea>` 自带 confirm-bar 计数，
但**小程序端没有**，且内置上限固定 140 不读配置 → 三端表现必然不一致。
修法：**关掉内置**(`:show-confirm-bar="false"`)，**计数一律自绘**：
- C 端 `.sf-textarea-box`(relative) + `<text class="sf-counter">{{ len }}/{{ max }}</text>`
- 预览端 `.cmpv-textarea-box` + `<span class="cmpv-counter">`
- 两者样式一致：`position:absolute; right: var(--c-input-pad-x,10px); bottom:6px;`
  字号/颜色走 `--c-prompt-size` / `--c-count-color`。
- 给 textarea 的 colorRows 补`countColor`（「字数统计颜色」def #909399），此前没定义会回落灰。

**验证**：C 端 `maxlength=400`、计数「0/400」在右下角(360,455)、高度 166；
设计器预览 `TEXTAREA` 标签、高 166px、计数「0/400」、right 10px —— **两端逐项一致**。
单测 21/21、审计脚本全绿、三端构建通过。截图 `verify-textarea-counter-c端.png` /
`verify-textarea-counter-designer.png`。

## 第 10 轮：选择类「选项类型」（文字/图片/图文）联动未复刻 — 纯死参数，已补齐

用户截图 ew 的单项选择有「选项类型」三选一，我方面板也有，**但切了完全没反应**。

**根因**：`content.optionType` 与 `opt.image` **两端渲染器都不消费**（全库grep 0 命中），
且 `components.js` 新建组件时**不声明该字段**（老数据 = undefined）。
此外 `imageText`（图文）档在面板上**连编辑入口都没有**（`v-if === 'image'` 才显示图片输入框），
即用户根本无法给图文选项配图。

**实现（三层）**
1. **数据层** `components.js`：radio/checkbox 默认 content 加 `optionType:'text'`，
   每个 option 加 `image:''`。
2. **渲染层**：两端各加 `optType(comp)` 兜底（`image`/`imageText` 之外一律 `'text'`）——
   老数据无该字段时若直接判 `=== 'image'` 会全部落到空档。
   - C 端 `SuperFormRender.vue`：选项行按 `optType` 挂 `.text/.image/.imageText` 类，
     渲染 `<image class="sf-opt-img">` + `<text class="sf-opt-label">`；
     选项区根节点挂 `opts-img` 变体（`flex-direction:row` 横向等分）。
   - 预览端 `ComponentPreview.vue`：同结构（`.cmpv-opt-img` / `.cmpv-opt-label` / `opts-img`）。
3. **样式参数**：schema 给 radio/checkbox 的 styleRows 加 `optionImgSize`(选项图片大小,def40,max120)
   + `optionImgRadius`(选项图片圆角,def3,max60)，标 `optImgOnly:true`；
   设计器 `curStyleRows` 过滤器扩展支持 `optImgOnly`（仅图片/图文时显示这��行）；
   `SIZE_VAR` 补 `optionImgSize→--c-option-img-size` / `optionImgRadius→--c-option-img-radius`。
   **顺带补漏**：`radioColor` 此前**没有 COLOR_VAR 映射** → `--c-option-color` 永远拿不到值，已补。

**踩坑**：给圆点/勾选框加 `order:-1` 想让它们在column 布局下居中，
结果它们被**推到选项行之外**（浮在选项区顶部）。圆点本来就是 DOM 第一个子元素，
column 布局自然落在图上方，`order` 完全多余 —— 两端均已移除。

**验证**（form 5 的 radio，三档逐一实测，C 端与预览端 class/布局/图数/文案数完全一致）：
