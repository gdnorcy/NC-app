## #237 纠正 sph 短链事实 + 主入口改为手动填 ID（用户质疑触发的事实复核）

main `5ccbdb71` / deploy `6bbe143d`，已上线。

**触发**：用户说「我之前的链接就是这个路径（/sph/）复制过来的」——据此复核发现**上一轮教程前提全错**。

**实测结论**（curl 可复现）：
- `weixin.qq.com/sph/A6FgtKSMRw` → 301 → `channels.weixin.qq.com/finder-preview/pages/sph?id=A6FgtKSMRw`
  → 第二跳直接 200 返回 SPA HTML，**feedId/finderUserName 命中 0 处**（短码是路由密文，服务端无法反解）。
- 该形态**不是「主页链接」**，而是微信 2026 改版后的**统一加密短链**，分享任何单条视频都长这样。
- 曾假设的 `channels.weixin.qq.com/...?finderUserName=&feedId=export/...` 明文参数链接是**旧版形态，微信已不再对外分享**。
- 合规解法只有官方口径（wx.openChannelsActivity 文档）：视频号助手首页取视频号ID（sph 开头）+「内容管理」取作品 feedId。
  逆向链路（`finder-preview/api/feed/get_feed_info`）需腾讯元宝登录 Cookie，第三方 API 要用户凭证 → 均不做。

**改动**：默认 `mode='id'`、标签顺序改为「填写视频号 ID」在前；链接模式顶部警示 sph 短链无法解析；
前端对 `/sph/` 先拦截再切模式；教程重写为助手四步图文；服务端 channelHomeLink 文案同步纠正。

**测试护栏**：`card-videos.test.js` 断言 channelHomeLink 文案须含「加密/视频号助手」，

### 🔴 元规则（本轮最大教训）
- **文档里的"平台事实"会过期，且过期后症状与"用户操作错"完全一样**。用户报错时先 curl 复现外部行为，
  再改代码；别信开发文档或自己几个月前的记忆。
- 写引导文案前必须问「用户手上**实际能拿到**的东西是什么形态」。我按旧形态写教程，
  等于让用户去找一个微信已经不给的东西——**比没有教程更糟**（会让人怀疑自己）。
- 服务端对外部链接的报错文案若含"操作指引"，一旦平台改版就会变成误导源；
  错误文案要回归护栏测试钉住负面断言（不得出现某短语）。

## #239 视频号作品 ID/封面提取器（用户问 res-downloader 引出）

main `19fc84b5`。用户问 `开发文档/res-downloader-master` 能否抓视频号封面和实际链接。

- 单一来源 `scripts/wx-channels-extractor.js` → `npm run build:feedid-helper` 生成油猴脚本 + 书签版

- 🔴 合规边界写进工具与测试：只读、不上传、不改写请求、@grant none

### 🔴 本轮两个测试教训
- **手抄正则的测试全绿是假绿**：第一版测试把 FEED_VAL 等正则抄了一份去测，真实实现有 bug 测不出来。

- **断言钉能力不钉函数名**：deepScan 重命名为 scanForFeeds 后，钉函数名的测试立刻红，

## 视频号：匿名 get_feed_info 实测终局 + 教程二次修正（2026-10-19）

### 用户截图带来的修正
用户真机截图证明：**手机端就能拿到视频号ID**（`sphJXxSYwt39JX5`，
路径「我 → 视频号 → 右上角人像 → 点头像进资料页 → 视频号ID → 点一下复制」）。
此前教程写「两个 ID 都必须开电脑 + 视频号助手」是**错的**，已改。
手机端**没有** feedId 官方入口（feed-token 那条路是给 channel-video 内嵌用的，
且要 mp 后台开「获取视频号视频ID权限」+ 仅 24h 生效），故作品ID 仍归助手。

### 匿名接口终局结论（三条，都实测过）
端点 `POST https://channels.weixin.qq.com/finder-preview/api/feed/get_feed_info`
body `{"baseReq":{"generalToken":""},"shortUri":"<sph短码>"}`
🔴 **必须带 Referer** `https://channels.weixin.qq.com/finder-preview/pages/sph?id=<短码>`，
   不带直接 401 `permission verification failed`；UA 必须是**移动端**（PC UA 同样 401）；
   `exportId` 形态入参恒 401。这三个条件缺一即失败——第一版漏 Referer 时「时灵时不灵」最易误判为限流。

| 字段 | 能否匿名拿 | 稳定性 |
|---|---|---|
| 封面 coverUrl | ✅ | `encfilekey` 恒定但 `token` 每次变；旧 URL 10 分钟后仍 200 → **要转存才稳** |
| 标题 description | ✅ | 稳定 |
| 作者昵称 / 头像 | ✅ | 昵称稳；headImgUrl 两次不同（CDN 多域名） |
| 点赞/收藏/评论数 | ✅ | 会变 |
| **feedId（长效）** | ❌ | 只有 `sceneInfo.dynamicExportId`，**每次调用都不同**且 ~2h 过期 → 不可存 |
| **finderUserName** | ❌ | 匿名响应完全不含 |

→ **结论：匿名接口只能解决「封面 + 标题」，跳转所需的两个 ID 一个都拿不到。**
   所以「粘贴 sph 短链一键添加」做不到，链接模式仍只能是次要入口。

### 教训
- 🔴 **「只解析了部分字段就下结论」= 新坑**：上一轮扫 response 时只看了 feedInfo/authorInfo，
  漏掉 `sceneInfo.dynamicExportId`，差点据此宣称「能拿 feedId」——如果那样上线就是
  「名片视频 2 小时后全废」。**拿 ID 类字段必须连调 3 次比对是否恒定**，名字带 dynamic 的要格外警惕。
- 🔴 接口「时灵时不灵」先怀疑**缺失请求头**而非限流：本次真实原因是 Referer，不是频率。

### 第二个样本复现（同日，用户新给的手机转发链接）
`https://weixin.qq.com/sph/AP55ngjIrq`（手机端视频号「转发 → 复制链接」）同样只能拿到

### 短链时效性（回答用户「链接是临时的吗」）
分两层：① 短链本身不是 2h 级临时货——用户 16 号复制的 `A6FgtKSMRw` 19 号仍 301 正常；
② 但每次访问签发的 dynamicExportId 恒为「now + 2h」且每次不同。
微信设计 = 短链当稳定入口 + 动态签发临时导出。官方未承诺永久，作者删视频/设私密即失效。
→ 故「链接适合发给朋友现在看，ID 才适合存进名片长期跳」，存 finderUserName+feedId 的方向不受影响。

### 🔴 决定性对照实验：同一条视频的「短链 ID」vs「电脑端真 feedId」
用户提供同一条视频的两个形态，直接把推论变成实证：

```
电脑端复制 : export/UzFfBgAAxLWAKGV6d16mk8zT4DCaU-3W21k6Dq2XPf5ODDSfKg
匿名接口给 : export/UzFfBgAAxLWAKGV6d16mk8zT4DCsIomrQQYsaBsIPUmjySbHWeT24TAw4g
             └──────── 前 34 字符完全相同 ────────┘└── 后 22 字符分叉 ──┘
             = 作品稳定主体                        = 签名/场景部分（需登录态）
```
（作品：东莞便民123「澄海湿地公园」；短链 sph/AQw28Htn9i）

结论：
1. **feedId 的前 34 字符是作品的稳定标识**，长效与动态版共享；分叉的尾部 22 字符才是
   需要登录态才能签出来的部分 → 这从结构上解释了「为什么匿名拿不到长效 feedId」。
2. 反向验证：拿电脑端长效 exportId 去查匿名接口 → 返回 `errMsg.type=2「此内容暂时无法播放」`，
   且**响应里依然 0 个 finderUserName/sph** → 视频号ID 仍只能靠手机端/助手拿，无法反查。
3. 方案不变，但结论从「推断」升级为「实证」：链接解析这条路在协议层就断了，
   教程引导取两个 ID 是唯一正解。
4. 顺带坐实 dynamicExportId 的「动态」是尾部轮换，存下来必废。
