### 🔴 高价值坑：微信「ticket 换图片」域名是 mp 不是 api
- `showqrcode` 的正确域名是 **`mp.weixin.qq.com`**，不是 `api.weixin.qq.com`。
  `api.weixin.qq.com` 是拿 access_token / 调业务 CGI 的网关，**上面没有 showqrcode 路由**，打过去一律 404。
- 而微信正用 404 表示「ticket 非法/过期」——两者状态码完全相同，**极易误判成 ticket 截断了 / 服务器出网失败**，白查半天。
- 实测：同一张 ticket `api.*→404`；`mp.*→200 image/jpg 430×430`。
- 已收敛为单一常量 `server/src/services/wx-mp.js#showQrImageUrl`（两处代理 + 两处 showUrl 全改），并加守卫测试锁死域名。代理 404 翻译成人话「二维码已失效或已过期，请重新生成」并回落 404。

## 🔴🔴 P0 根因定案：被动回复的 FromUserName 必须是公众号原始ID（不是 appid）
> 此前 5 轮排查全部跑偏在「条数 / 图片格式」上（都判错了）。这一节是完整证据链，细节不再进 MEMORY.md。

### 症状
公众号扫码推事件后，粉丝端一律「该公众号提供的服务出现故障，请稍后再试」；服务端视角一切正常（HTTP 200 / XML 合法 / 字段不超限 / 图片 200 可访问 / 条数合规）。

### 根因（协议级）
微信推过来的报文里 `<ToUserName>` = **公众号原始ID**（`gh_` 开头）；被动回包的 `<FromUserName>` 必须原样写回它。
我们从头到尾填的是 `channel.appid`（`wx_` 开头）→ 微信判「回复了异常数据」→ 整条丢弃。
官方口径：开放社区技术运营「FromUserName 不应该是 appid，而是公众号原始 id，你服务器接收到微信推给你的原 ToUserName，一般是 gh_ 开头的」；
开放文档「FromUserName：公众号/小程序原始ID」。密文回包的**尾部标识**同理（`WxCrypto.encrypt` 尾部也应是原始ID）。

### 上一轮结论为何是错的（重要教训）
- 「微信服务器抓图失败 → RGBA PNG 导致抓缩略图失败」**误判**：那些 `UA=Mozilla/4.0 / Referer=-` 的图片请求是**用户微信客户端**加载 H5 页/历史卡片，
  同一时间并没有对应的 `POST /api/channel/wx-message/...` 回调 → 不能当「微信服务器抓缩略图」的证据。
- 「条数超限导致整条拒收」**误判**：故障时段回的是 **1 条**（ArticleCount=1）也照样报错；微信对超条数是「只发限制内条数」而非报错。
  客服接口 `45008 article size out of limit` 是**客服接口**的限制，不能外推到被动回复。
- 「RGBA PNG 有 alpha 微信不支持」**未证伪也未证实**：故障前后都用过 JPEG（展示位封面 02334.jpg）当 PicUrl，故障依旧 → 图片不是根因。

### 决定性证据
1. nginx access.log 逐条比对 `POST /api/channel/wx-message/...`：**真实微信回调的 body_bytes_sent 只有 779~871 字节**（1 条图文），
   而本地探针 1427 字节（3 条）→ 微信确实收到了我们的回包，是被它自己判非法。
2. 生产 `mp_message_config.encoding_aes_key` 有值（安全/兼容模式），但回调 URL 参数是 `signature` 而非 `msg_signature`
   → 账号是**明文/兼容模式** → 加密尾部不是本次根因（但仍按协议修对了）。
3. `account/getaccountbasicinfo` 对该订阅号返 **48001 api unauthorized** → 原始ID **没有开放接口可查** → 只能从入站报文自动学。
4. 官方文档 + 开放社区答复明确 FromUserName 口径（见上）。
