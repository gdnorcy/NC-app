### 标题不居中（用户反馈：很多页面标题都不居中）
**Shared root cause**：pages.json 大量页面 `navigationStyle:'custom'`，标题由
`PageNav.vue` / `DesignNav.vue` / `DesignNavEw.vue` 三个组件自绘，三处都是同一个写法：

**额外踩到**：DesignNavEw 的 `.dnew-title-text` 是 `width:100%`，撑满后 flex 的 justify-content 失效，

**根因是外壳层叠，不是某一个值写大了**：装修页给每个组件套了三层带内外边距的壳——
`.ce-body`（左右 space-r5=12px）+ `.ce-card`（左右 space-r4=10px）+ `.ce-render`（左右 space-r2=6px）
= 左右各 28px + 卡片上下 4px padding + 6px 间距，**组件被凭空捏窄约 32px**；
而 `.ce-card` 还有白底+圆角 → 组件看着像装在盒子里预览，而非嵌在名片里。

**修复（删壳，不调值）**：
- `.ce-body` 左右 `space-r5 → space-r4`（12px → 10px）
- `.ce-card` 只留 `padding:var(--space-r1); margin-bottom:var(--space-r2)`（4px/6px），**去掉底色**（母版 lock 才给 `--bg-card`）
- `.ce-render` 只剩 `position:relative; overflow:hidden`，**零 padding/margin**
- 净值：装修页左右留白 = `space-r4(10px) + space-r1(4px) = 14px`，与真实名片页 `.cc-list { margin: 0 28rpx }` 的左右各 14px **逐像素一致**（375px 屏 Chrome DOM 实测差值 0.00px）

**教训**：
1. 🔴 **「间距不真实」先数壳层数**：三层壳各 4~12px 是「每层都合理、加起来失真的」典型——
   调参永远调不对，要**删层**。WYSIWYG 页面只允许「一层内容边距对齐真实页」。
2. 🔴 **选中环不能画在 `.ce-card` 边框上**：`border:1rpx` 会各占 0.5px 把组件捏窄 1px，
   破坏与真实页的像素对齐 → 独立绝对定位 `.ce-ring`（`pointer-events:none`），零布局影响。
3. 验证必须**比产物内容**：H5 构建会把 rpx 转 rem（`1rpx → .03125rem`），
   且 CSS 选择器带 scope 后缀（`ce-card[data-v-xxx]`）→ `grep -oE "\.ce-card\{..."` 恒 0 是假阴性，
   要去掉类名前的点或先查原文。
4. 部署：main `a2bb2ef0` → deploy `89a4ccb4`，外网两个 chunk（css 10754B / js 19968B）md5 与本地一致。

## 🔴 第四次返工：编辑器 vs 预览「两张皮」——病根是 ce-card 的间距外壳
用户截图对比后反馈：「设计和预览差距还是有点大，主要是组件与组件的间隔」。

**没有继续凭感觉调参，而是写最小化测量页 + Chrome headless 实测五场景**（375px 视口、1rpx=0.5px、
组件用真实 notice/video/img-fallback 标记与真实 CSS 值复刻）：

| 场景 | 左右留白 | 组件宽 | 组件间距 |
|---|---|---|---|
| 真实名片页 `.cc-list{margin:0 28rpx}` | 14px | 327 | **6px**（组件 marginTop 默认值） |
| 编辑器（修复前） | 14px ✓ | 327 ✓ | **20px** ✗ |
| 预览层（修复前） | 12px ✗ | 331 ✗ | 6px ✓ |
| 编辑器/预览（修复后） | 14px ✓ | 327 ✓ | **6px** ✓ |

**间距 20px 的构成**（每层单看都"合理"，所以前两轮都没揪出来）：
`.ce-card{padding:4px}` 下边 4 + `margin-bottom:6px` 6 + 下张卡 padding 上边 4 + 组件 marginTop 6 = **20px**。
预览层没这些外壳所以是 6px；真实页 `.cc-list` 是 flex column 且项无 padding，也是 6px。

**修法（main `f933fbac` → deploy `9f3098ba`，外网 md5 一致）**：
- `.ce-body` 左右 `space-r4`(20rpx) → **28rpx**（补偿卡片原来的 4px padding；与 `.cc-list` 同值，
  且 padding 不在 tokenAudit 管辖范围——已核实只扫 hex/rgba/font-size/border-radius/box-shadow/z-index）
- `.ce-card` 删掉 `padding` 与 `margin-bottom`，只留 `position:relative`（环/浮条/徽标的定位基准）
- `.ce-preview-canvas` 左右 `space-r5`(24rpx) → **28rpx**（预览=真实页宽）
- 间距从此 100% 由组件自身 marginTop 决定，三场景 x/width/gap 全等

**新沉淀的方法论**：
1. 🔴 **「A 和 B 不一致」先各测一遍再改**：用户说"差距大"但没说谁对。测量页五场景并列，
   一眼看出真实页=6px 是基准、预览差在宽度、编辑器差在间距——**没有测量就会三个都瞎调**。
2. 🔴 **flex column 子项不吞子元素 margin**（实测纠正了我的 spec 记忆）：曾担心 `.cc-list`
   的 flex item 会把组件 marginTop 关在项内导致真实页 0 间距，headless 实测是 6px。
   **spec 记忆与实测冲突时信实测**。
3. 提案类要**完整覆盖原类**：测量页第一版 `.ce-card-fix` 忘了写 `padding:0; margin-bottom:0`，
   和 `.ce-card` 同时挂类时原声明仍然生效 → 测出 20px 以为提案无效。**覆盖式修复类必须显式归零**。
4. 环/浮条/锁徽标现在是「压角浮标」（卡片零 padding 后 4px 内嵌即压在组件角上），
   与 PC 设计中心同思路；注释同步更新，免得后人看到"贴卡片内沿"的旧注释又加回 padding。

- 🔴 **「跳转类型」radio 的空值陷阱**（两端通病）：`options[0].value` 会被当默认值顶上去
  → 新增按钮默认变成第一个外链类型。凡「允许不选」的 radio，schema 必须显式 `default: ''`。
- 🔴 **子组件自身配置 vs 父级配置**：按钮组的每个按钮有**独立**链接配置（存在 `buttons[]` 里），
  组件级 `props` 上没有 `linkType`。渲染时若只传组件级 → 外链永远跳空（静默失败）。
  判据：**渲染层拿到的配置对象，必须和配置面板编辑的是同一个层级**。
- 🔴 **产物「未跟踪计数为 0」不等于没变**：被 .gitignore 的目录（`/server/public/card/` 等）
  下新增文件不会出现在 `git status` 的 `??` 里 → 必须用 `comm` 对比索引与磁盘清单，
  并用 `git add -f` 显式入库。

- ⚠️ 元素截图（`locator.screenshot()`）截的是**元素可见部分**，页面滚动位置在中间时

## #321 收尾自查：symbol 埋下的「两端各自配了不生效」（自主发现并修）

用户四条反馈（#321-#324）上线后自查发现**我自己在 #321 埋的缺陷**：
`symbol` 同时进了web-app 与 web-admin 两端 registry（面板能配），
但渲染只补了名片那一份（`CardCompItem.vue`）→ 两端各有一处「配了没反应」：
- **admin 设计器画布配了符号，预览不显示**（所见非所得，最阴）；
- **首页/商场装修（`DesignPage.vue`）配了符号，C 端不显示**。

上一轮我在 `noticeSymbol.test.js` 注释里写「两端收敛是另一件事，不要在本次顺手改」
——判断错了：那不是「另一件事」，是**本次改动自己造的缺口**，留着就是埋雷。

### 修法
抽 `web-app/src/utils/noticeSymbol.js` 单一事实来源（符号表+ 面板选项 + 归一化/解析），
三处渲染（CardCompItem / DesignPage / admin ComponentRender）与两端 registry 全部引用。
admin 跨包 import 沿用 `containerStyle.js` 的既有模式。

要点：
- 形状类 `shape` 存**完整类名** `is-dot`（不让各端自己拼 `is-` 前缀 = 漂移源）；
- 字符类仍写码点 `\u2713` / `\u2605`；
- `noticeSymbolParts()` 两字段恒为字符串，**按空串短路整个元素**（空壳白占 flex 槽位 + 抢 gap）；
- `symbol` 与 `iconType` 必须串进**同一条 v-else-if 链**，否则「公告」标签和符号一起画；
- admin 画布尺寸按「375px 基准 = 750rpx」折半（8rpx→4px）。

### 🔴 写"跨端一致性"测试的三连坑（本次全踩）
1. **非贪婪正则跨界**：`key: 'symbol'[\s\S]{0,700}?options: \[\{` 跨界吃到**下一条 schema**
   （symbol 后面紧跟 align，align 本就写字面量 options）→ 恒假失败。
   判「某条 schema 没手抄」必须**只看它自己那一行**。
2. **`v-else-if` 不是 `v-if`**：正则 `/v-if=/` 判不出合法的 else 分支 → 用 `/v-(?:else-)?if=/`；
   断言「元素被条件短路」要**按标签边界取**（`/<[a-zA-Z][^<>]*>/` 里找带该 class 的那个），
   写 `v-if="[^"]*${cls}` 会在属性顺序颠倒时误报。
3. **别写恒真断言**：我一度写成 `'x'.replace(...) && 'text-inline'` 这种废话表达式，
