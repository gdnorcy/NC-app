### 🔴 根因修复：切分支删本地小程序产物
之前记过「切回 main 后 mp-weixin 只剩 BUILD.txt」的**现象**，今天定位到根因：
`deploy` 分支此前 `git add -A -f` 时**误跟踪了 `web-app/dist` 下 499 个构建缓存**（`ls-tree deploy`=499，
而 main 因 `.gitignore` 有 `/web-app/dist/` 而=0）→ 从 deploy 切到 main 时 git 会「删除本地这些文件」。
**修法**：deploy 上 `git rm --cached -r -q -- web-app/dist` + commit + push。之后切 main 不再删产物（已实测：
切回后 app.js/app.json/app.wxss/project.config.json/cardEdit.wxml/wxss 全在）。
配套教训：**以后 deploy 的 `add -f` 必须限定到 `server/public/{card,mall} server/mini-template/mp-weixin` 三个具体目录，
不要用 `-A`。**

## 全站自绘导航「标题不居中」+ 预览入口位置

### 标题不居中（用户反馈：很多页面标题都不居中）
**Shared root cause**：pages.json 大量页面 `navigationStyle:'custom'`，标题由
`PageNav.vue` / `DesignNav.vue` / `DesignNavEw.vue` 三个组件自绘，三处都是同一个写法：
行内 flex「左操作 / 标题 flex:1 / 右操作 + 右侧胶囊避让」，标题居中基准是**剩余空间**，
而左侧让出返回键≈26px、右侧让出整块胶囊区≈94px → **两边不等宽，中心必偏向返回键**，
且左右内容越不一样宽偏得越多。
**正解（微信原生口径）：按屏宽居中**——
① 行加 `position:relative`；② 标题 `position:absolute; left:0; right:0`（abs 参照 padding box，
覆盖含左右 padding 的整行 → 基准=屏宽）；③ 用 `navTitleSafePad()` 下发**左右同值** padding 兜重叠；
④ 标题层 `pointer-events:none` + `.cls > * {pointer-events:auto}` 让点击穿透给左右操作。
⚠️ 两侧 padding 必须同值，一边大一边小等于把偏移又写回来。
新 `web-app/src/components/navTitleCenter.test.js` 6 例钉住（含负向：不许写 `flex:1`、不许非对称 rpx padding）。
**额外踩到**：DesignNavEw 的 `.dnew-title-text` 是 `width:100%`，撑满后 flex 的 justify-content 失效，
必须补 `text-align:center` 才真的居中。

### 测试写法坑（新）
🔴 别用 `/\.cls \{[\s\S]*?xxx/` 取 CSS 规则体：非贪婪会跨过 `}` 吃到**后面无关规则**的声明
（实测 `\.dnew-title \{[\s\S]*?flex: 1;` 命中的是 `.dnew-search-txt`），通过/失败都是假的。
必须按大括号切到本规则 `}` 为止（见 navTitleCenter.test.js 的 `cssRule()`）。

### 预览入口位置（用户反馈：组件多时要拉到最后才能预览）
- 改成**双入口**：① PageNav 右插槽常驻「预览」（nav 是 sticky，滚动位置无关；标题已绝对居中，
  加右插槽不会把标题挤偏——这正是绝对居中的副收益）② 底部按钮包一层 `.ce-preview-bar-wrap`
  `position:sticky; bottom:0` + 自带页面底色（防列表内容从胶囊按钮两侧透出）。
- 沿用既有纪律：可滚动容器里的主操作按钮要 sticky，否则用户报「找不到按钮」。

### 本轮踩的三个坑（都是流程坑，不是代码坑）
1. **python 整块替换模板会打破标签平衡**：`s.slice()` 拼接时吞掉了 cardDetail 里 intro tab-panel 的
   `</view>` → uni build 报 "Element is missing end tag"。**972 条单测全绿也拦不住**，只有真构建才暴露。
   → 教训：大块模板改造后必须**真跑 uni build**（别用 `npx vite build` 代替），并在替换后 diff 校验 `</view>` 计数。
2. **别用 `npx vite build` 做快速验证**：它会在 `web-app/dist/build/h5` 留残缺产物，
   正式构建时清理 81 个旧文件 → 撞 safe-delete 守卫（>50），后续正式构建直接挂。

3. **分支纪律差点违规**：我先 `git checkout deploy` 后再 commit 修复 → 源码提交落到了 deploy。
   纠正顺序：**先在 deploy 提交产物** → `git checkout main` → `git cherry-pick <deploy 上的修复>` → push main
