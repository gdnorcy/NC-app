## #312 第十八轮：登录不再跳两次页面（改为页面内原地登录）

反馈：「现在登录要跳两次页面」。链路：`我的名片`(未登录) → reLaunch 到
`pages/cardMain/login` → 登录完再 reLaunch 回名片页，**去、回各一次跳转**，
用户看着两个页面各闪一遍。

修法（通用思路：别用「跳出去再跳回来」触发状态刷新）：
1. 登录请求收敛到 **`utils/inlineLogin.js`**（`fetchLoginCode` / `performWxLogin` /
   `mustCreateCard`），登录页与页面内浮层共用一份——否则 H5 模拟码、租户兜底
   `DEFAULT_TENANT_ID`、登录后 `resetBrandCache` 三条任一条漏写就是「能登录但首页空白/品牌色不对」。
2. 新组件 **`components/LoginGate.vue`**：未登录占位视图里直接放「微信一键登录」+ 协议文案，
   点一下就地登录（busy/inflight 双闸防连点——微信 code 一次性）。
3. myCard 把 `onMounted` 里的进入流程抽成 **可重入的 `bootOwner()`**，登录成功后
   `notLogin=false → await bootOwner()` 原地进入；**0 次跳转**。
   只有 `mustCreateCard`（新用户/没名片）才跳一次 `/pages/card/create`（否则落在空壳页）。

踩坑与教训：
- 既有 `brand.test.js` 钉的是「login.vue 必须 import resetBrandCache」这种**写法**，
  实现搬走就红。改钉**语义**：inlineLogin.js 调了 resetBrandCache + 两条入口都走 performWxLogin
  + 入口里不许再出现 `cardApi.wxLogin(`。
- 模板里 ref 不带 `.value`（写 `busy.value ? …` 在模板里不生效），测试断言也要按模板形态写。
- MP 端确认三处齐全才算挂上：`components/LoginGate.{js,json,wxml,wxss}` +
  页面 `myCard.json` 的 `usingComponents` + wxml 里的 `<login-gate bindsuccess=>`。
