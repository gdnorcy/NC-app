## MP 真机启动崩溃修复：import.meta 防御写法被编译成 require("url")
- **现象**（用户提供的 devtools 日志）：`Error: module 'utils/url.js' is not defined, require args is 'url'`，栈顶 `apiBase.js:1 ← require(utils/apiBase.js) ← cardApi.js:1`；连带 `app.js错误`、`Page "pages/cardMain/login" has not been registered yet`、`Component is not found in path "wx://not-found"`——app.js 启动即崩，全页面未注册。
- **根因**：apiBase.js 里 `typeof import.meta !== 'undefined' && import.meta.env` 的防御式写法。vite 在 MP（CJS 输出）下把**裸 import.meta** 垫片成 `{url: "undefined"==typeof document ? require("url").pathToFileURL(__filename).href : ...}`——H5 有 document 走浏览器分支无事，MP 无 document → 编译出 `require("url")` → 微信运行时无此 Node 内置模块 → 崩。直接写 `import.meta.env` 才会被 define 整体替换成字面量，不留裸 import.meta。
- **修复**：① 改 `const env = import.meta.env || {}`（vitest/node 下 .env 为 undefined 走默认值，安全）；② IS_MP_WEIXIN 去掉模块加载期的 `uni.getSystemInfoSync` 探测（window/wx 判据已足够，顺带消除日志里连片的 deprecated 警告）。新编译产物：`const _={VITE_MP_API_BASE:"https://zero.nshop.mobi",VITE_H5_API_BASE:""}||{}` + `"undefined"==typeof window&&void 0!==o.wx$1`——零 require("url")。
- **测试**：新增 `apiBase.test.js` 7 例（取值 + 源码模式红线 + 构建产物条件检查）；注意反面写法不能出现在注释里被正则误抓——测试先剥注释再断言。全量 864 绿。

## SaaS 架构核查：appid 官方分工与多租户路径（用户提问）
- **官方要求**：appid 属前端配置（manifest.json→mp-weixin.appid，每包唯一、上传定归属）；secret 只能服务端（jscode2session 用，进前端 bundle=可反编译泄露）。当前「appid 前端 + appid/secret 后端」= 标准分工，无问题。
- **当前租户模型**：单 appid + 应用内多租户。租户=customer_id（projects 表）；wx-login 靠 body.tid 或 config.defaultTenantId 兜底绑定（多租户平台部署设 DEFAULT_TENANT_ID=0 关闭）；所有租户 C 端用户同属一个小程序的 openid。
- **多小程序租户的官方路径**（若产品要「每客户自己的小程序」）：① 第三方平台/服务商模式（开放平台资质+授权+component token，当前代码零支持）；② 一码多包（每租户构建填各自 appid，后端 appid→secret 改按租户查表，createWxCode2Session 从单例改按租户解析）。现状定位=单小程序内部分租户，够用。

## 架构定方向：微信第三方平台代开发模式（10-17 用户拍板方案）
- **用户方案**（两张设计图确认）：每客户一个自己的小程序，SaaS 化。① 总后台「系统设置→第三方平台配置」：component AppID/Secret/Token/AESKey + 授权事件接收URL + 消息接收URL(`$APPID$` 占位符)，平台状态等 verify_ticket 推送；② 客户侧「参数设置」：原始id/Appid/AppSecret/代码上传密钥(IP白名单) + 「取消第三方授权」。对标 cloud.xincainiao.cc/index/index/wxset?appletid=10（需登录）。一套代码做**代码模板**代上传代发布。
- **核心技术点**：component_verify_ticket(10分钟一推)→component_access_token 是发动机；jscode2session 必须改 `sns/component/jscode2session`（component token+authorizer_appid），现有 app.js 单例 appid+secret 作废；消息 URL 的 `$APPID$` 是官方占位符；代码上传密钥白名单要含服务器出口 IP；需企业主体+开放平台认证 300元/年。
- **现状**：代码零 scaffolding（无 channel 端点、无 component 概念）；域名 zero.nshop.mobi 已 SSL 公网可达可直接做回调。
- **推进建议**：最小闭环=平台配置+回调端点+按租户登录，再代上传代发布+消息转发。待用户确认后出正式改造方案文档。
