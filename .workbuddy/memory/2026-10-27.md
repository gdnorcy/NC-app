### 病根不是布局重复，是「同一页显示两个不同等级名」
用户原话「个人中心和会员中心是不是有点重复，或者是说不出的感觉」。核实后定位到真因：

### 踩坑记录
- `node --test $FILES`（变量多文件）会被当成**单个路径**参数 → `Could not find 'a.js b.js'`。必须 `$(cat list.txt | tr '\n' ' ')` 展开。
- `node:sqlite` 的 `run()` 返回属性是 **`lastInsertRowid`**（小写 d），项目 257 处都是这个写法；写 `lastInsertRowId` 得到 undefined → `Provided value cannot be bound to SQLite parameter N`。
- CSS 注释里写 `/* ... .si-*/ ... */` → 注释被提前闭合，后半段变成真 CSS。断言「样式块不含某选择器」时会误判残留。写注释别在括号里放 `*/`。
- 配色回归锁 `memberColorSystem.test.js` 锁的是**元素名**：删元素必须同步改锁，否则红一片（本轮 6 项失败）。
- `themeColor` 看似死变量（全站品牌色口径约定，`brandCoverage.test.js` 逐页扫这一行）→ **不要删**，删掉破坏一致性契约。
- `lastInsertRowid` / `scope` 类断言要注意：`ruleBlock()` 只匹配**首个**规则块，`.tlv-detail` 若写成复合选择器要留意。

### ① 会员等级 Lv 序号错乱（黄金会员 Lv1、免费版 Lv2）
- 根因链：`addLevel` 默认 `level_no=1` → 管理员先自建「黄金会员」抢到 Lv1 → `ensureTenantDefaultLevels` 播种「免费版/白银」按 MAX+1 顺延得 2/3 → 轮到「黄金会员」同名**认领**（只打 pkg_level 标记，保留原 level_no）→ 标准档相对序错乱。C 端档位条与后台列表都按 `level_no ASC` → 高档排最前。
- 修复（server）：
  - `db.js ensureTenantDefaultLevels` 尾部加 normalize：**仅当**标准档之间不满足 free<silver<gold<diamond 相对序时重编（标准档按模板序优先，自建档按原序排其后，level_no+sort_order 同步）；相对序正确时一律不动（管理员手动调序不被每次启动的播种覆盖）。
  - `member.js addLevel` 默认序号改 `MAX(level_no)+1`（不再写死 1）。
  - 存量错乱租户由启动时 `seedTenantMemberPackages` 自动修复（normalize 幂等）。
- 新测试 `server/test/member-levelno-fix.test.js`（3 项）：错序自动重编 / 不错乱不覆盖 / addLevel 默认 MAX+1。

### ② 分销配置「指定商品」手输 → 点选（web-admin DistHome.vue）

### ③ 会员中心空白页（C 端 member.vue）
- 真因：旧版本页有一张**不受 v-if 控制的分销大卡**垫底；上轮迁走后暴露「游客/请求全失败时数据全空 → 页面只剩 hero+tabbar」。onMounted 的 Promise.all 任一 reject → catch 吞掉 → 三个内容区全隐藏，且 tenantUnbound 仍 false → 连未入驻引导都不显示。
- 修复：加载逻辑抽成可重入 `loadMemberData()`（「登录跳两次」通解）；兜底卡条件改 `!showTenantMember && !appBenefits.length`，三态：未登录→「去登录」（requireLogin 成功后原地重入）/ 未入驻→原引导文案 / 已登录但请求失败→「重新加载」。
