## 公众号自定义菜单：三个灰选项可点 + 官方版式二次对齐（需求I）

### 权威口径（WebFetch 官方文档 api_createcustommenu，2025-11-25 最后编辑）
- `menu/create` 的 type 枚举**只有** 12 个：click/view/scancode_push/scancode_waitmsg/pic_sysphoto/pic_photo_or_album/pic_weixin/location_select/media_id/article_id/article_view_limited/miniprogram。
  **没有**「跳转小店 / 跳转商品 / 跳转账号主页」—— 这三个只存在于微信网页版编辑器 UI。微信社区官方回复「不支持」；但小程序场景官方推荐落地 = `miniprogram` type + 小店小程序 appid + pagepath。
- 名称长度：一级 ≤4 汉字（≤16 字节），二级 ≤8 汉字（≤60 字节）；超长报 **40018 invalid button name size**。实测口径 = units（汉字算 2、字母算 1）+ UTF-8 字节双闸，emoji 计 1 unit 但占 4 字节（字节闸会先拦）。
- 开启服务器配置后菜单只能 API 创建，网页端后台菜单失效（社区已确认）。

### 架构决策：UI 语义类型 vs 微信真实 type 分层

## 「消息加密 / 数据格式」两个选项：确认不提供（含两个静默事故点的补齐）

## 🔴 回调 URL 拼成 http 导致公众号后台「请求失败，HTTP 返回非 200」（线上真事故）

### 故障与根因链
用户截图：公众号后台提交服务器配置报「请求失败，HTTP 返回非 200」；我们后台显示的回调 URL 是 **http** 开头。
链路（线上已核实 nginx 配置）：
- `server { server_name zero.nshop.mobi _; location / { proxy_pass http://127.0.0.1:3000; proxy_set_header X-Forwarded-Proto $scheme; } listen 443 ssl; }`
- 另有一个 80 端口 server：`if ($host = zero.nshop.mobi) { return 301 https://$host$request_uri; }` 之后兜底 `return 404;`（certbot 生成）
→ Nginx 在 443 终止 TLS 后以**明文 http** 反代到本机 3000，`req.protocol` 拿到的是这一跳的协议 = **http**，
  所以回调 URL 是 http；微信拿 http 地址做验证，要么撞 301（Host 匹配）要么撞 404 → 「HTTP 返回非 200」。
  报错信息完全不提示是协议写错，排查成本极高。

### 修法：`server/src/utils/publicUrl.js`（对外基址唯一出口）
取值优先级 **PUBLIC_BASE_URL > X-Forwarded-Proto/Host > req.protocol+Host**（无反代头时退回真实协议，本地 http 开发行为不变）。
收口 12 处原先手写 `req.protocol + req.get('host')`：customer(5)、channel(2)、trace(2)、plans、content、openapi，外加 card.js 两处重复造轮子的 XFP 手工判断。

### 🔴 我这次踩的坑（脚本批量改 multiple files）
- 用 python 批量插 import 时按「最后一行 `import ` 开头」定位 → **插进了 customer.js 的多行 `import {` 语句中间**，
  整个文件 ESM 解析失败（全套测试瞬间 60+ 失败）。必须按分号/import 语句真实结束位置插，或直接单独 Edit。
- 相对路径算错：`src/routes/x.js` 应是 `../utils/`，按文件路径层级算成了 `../../utils/`。改完必须 grep 核对每个 import 路径。
- ⚠️ `git commit -m "...${req.protocol}..."` 在 zsh 里会 bad substitution（双引号内的 `${}` 被当变量）→ 多行提交信息一律用 `git commit -F - <<'EOF'` 单引号 heredoc。
- `node --check src/x.js` 对 type:module 项目仍按 CJS 解析 → 报「Unexpected reserved word」是**假阳性**，别据此改代码；真实校验用 import/跑测试。

### 线上部署
- 生产 `server/.env` 追加 `PUBLIC_BASE_URL=https://zero.nshop.mobi`（先 `cp .env .env.bak_<时间戳>`），双保险：即使哪天反代头没传也对。

  再去掉 env 只给 x-forwarded-proto 复验一次，两条路径都要对。

## 微信「JS 接口安全域名」验证文件托管

### 背景
公众号后台「编辑 JS 安全域名」会要求下载 `MP_verify_xxxx.txt`，并要求能通过 `https://域名/MP_verify_xxxx.txt` 直接取到明文。

### 关键事实（踩点）
- 🔴 **该 Node 服务没有把 publicDir 整目录挂在根上**：静态一律走前缀（`/uploads`、`/admin-assets`、`/card`、`/mall`、`/pano`、`/gift-share`、`/goods-style`、`/images`）。
  → 把 txt 直接丢进 `server/public/` **取不到**，必须有根路径路由。
- 现在的实现：`app.js` 里 `app.get(/^\/MP_verify_[\w-]+\.txt$/, ...)` 从 `MP_VERIFY_DIR`（默认 `server/public/verify`）直出 `text/plain`；
  只认 `path.basename`（防路径穿越）；文件缺失走 `next()`，不吞后续路由。
- 落盘目录 `/opt/app/server/public/verify/` 已加进 .gitignore（文件名随域名变更而变，不入库）；`git reset --hard` 不会删未跟踪文件，安全。
- 本地冒烟方式：`printf 'selftest-ok\n' > public/verify/MP_verify_selftest.txt` 起服务 → `curl http://localhost:3000/MP_verify_selftest.txt` 应 200 + 原文；不存在时 404。

### 坑
- ⚠️ TAT 对 **nginx 80 端口**（`http://127.0.0.1/...`、带 `Host:` 头的请求）一律 AccessDeny；只有 `:3000` 直连能打。要验公网链路就让用户浏览器访问，或改用 `curl -H Host` 之外的方式都被拦。
- 本轮 `deploy` 合并后 push 被 SIGTERM(137) 打断，merge 已成但 push 没成 → 重推前先用 `git ls-remote` 确认远端再 push（别重复合并）。

## 防伪溯源：库存与「充值库存」的真实语义（用户提问核查）

### 结论
- 库存列 = `trace_settings.cocom`（**独立列**，不是 settings_json 里的键 —— 早期 bug 就是读错了地方导致每次充值都覆盖而非累加）。
- **`-888` = 不限**；`>0` 有限；`0` 无库存。`deductCocom()` 见到 -888 直接放行且不扣减。
- **新租户首次访问懒初始化为 -888**（`getSettings` / `saveSettings` 都是），目的是避免「应用一开通就生成不出码」。
- → 所以在「不限」状态下点「充值库存」是**空操作**：`next = current === -888 ? -888 : current + amount`，只往 `trace_histories` 多写一条 `recharge` 记录（备注「充值防伪码库存：+1000，当前 不限」）。
- 库存真正的区分点在平台侧有没有把 cocom 改成有限值；改了之后充值才生效。

### ⚠️ 发现的权限/风控缺口（未修，待用户决策）
`POST /api/customer/trace/recharge` 只过了 `requireTenant`（`tenant_admin` **和 `tenant_member** 都能调），没有 requireTenantAdmin、没有数量上限、没有支付/发放凭证校验、也没有平台级 audit（只写 trace_histories）。
→ 一旦某租户被改成有限库存，任意普通成员都能给自己无限加额且全程免费无凭据。
建议改法（待确认）：① 收紧到 requireTenantAdmin；② 充值入口挪到平台侧、由发放记录驱动；③ 留 audit + 单次上限。
