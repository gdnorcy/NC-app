# 应用架构规范

## 方案化两级权限模型
**方案 = 组合包，不是应用**：
1. 应用（apps表）是平台级功能单元；解决方案（solutions表）是组合包
2. 两级权限：应用级存 solution_apps；菜单级存 solution_permissions（含 app_id）
3. 演示方案（code='demo'）自动纳入全部应用且菜单全量授权
4. 保存权限必须传全量 apps+menus（整体替换）
5. 租户授权判定：tenant.js hasSolution 兼容直接开通与组合包

## 应用内 Tab 模式
- 每个应用的业务管理页面统一收敛在应用内 Tab 导航（CardTabs 模式）
- 侧边栏禁止新增应用级菜单，一律放应用内 Tab
- **选项卡栏常驻**：只要页面是顶部 Tab 应用内页面，必须渲染对应 Tabs 组件，禁止打开某 Tab 后选项卡栏消失

## 前端 API 调用规范
- adminApi baseURL=/api/admin、customerApiCall baseURL=/api/customer，调用时 URL 不得重复前缀
- 响应拦截器已解包，组件内直接取 res.xxx，禁止 res.data.xxx
- catch(e) 直接 ElMessage.error(e)，禁止 e.response?.data?.error
