# 构建部署规范

## 常用命令
```bash
npm run build:admin      # 构建管理后台（自动清理旧产物）
npm run build:mobile     # 构建移动端H5
npm run build:all       # 构建全部
npm run verify           # 验证构建产物
npm run restart         # 重启服务器
npm test                 # 后端测试（全量用串行：node --test --test-concurrency=1 server/test/*.test.js）
npm run test:frontend    # 前端单元测试
```

## admin产物路径
web-admin 的 vite `outDir` 已直接指向 `../server/public/admin`，`npm run build`（或 build:admin）产物即被 3000 服务托管，**无需手动同步**。浏览器验证必须带 cache-busting query（如 `?_=v1`）强制换新文档，否则可能加载旧 JS 看不到改动。

## H5产物同步
uni-app 构建输出在 web-app/dist/build/h5，需同步到 server/public/card：
```bash
rm -rf server/public/card/assets/* server/public/card/index.html
cp web-app/dist/build/h5/index.html server/public/card/
cp -R web-app/dist/build/h5/assets/* server/public/card/assets/
```
**必须先删再拷**，禁止直接叠加（旧chunk残留污染验证）。

## 缓存策略
- HTML：Cache-Control: no-cache
- JS/CSS：public, max-age=31536000（文件名带哈希）
- 关键：构建前必须清理旧产物

## 踩坑记录（先读）
- **重启服务**：`npm run restart` 的 pkill 模式（`node server/src/index.js`）匹配不到实际进程（实际是 cwd=server 的 `node src/index.js`），重启不生效且 3000 仍被旧进程占用。正确做法：`lsof -nP -iTCP:3000 -sTCP:LISTEN` 找 PID → `kill <PID>` → `cd server && nohup node src/index.js > /tmp/nc-server.log 2>&1 &` → `curl /api/health` 确认 uptime 很小、PID 已换。
- **根 workspaces**：目录是 `server / web-app / web-admin`，workspaces 必须写真实目录名。曾写 `web`（目录已改名 web-app），`npm run build:mobile` 报 "No workspaces found"。修正后 `npm run build:mobile` 正常。
- **db.js 迁移位置**：`migrate()` 里新增 ALTER 必须放函数尾部（如 normalizeProjectSolutions 之后、幂等 colExists 包裹）；禁止插进 `db.exec('...')` SQL 字符串中间，会触发 SQL 语法错误且启动即崩。
- **小程序构建**：`npm run build:mp-weixin -w web-app`，产物在 `web-app/dist/build/mp-weixin/`（含 app.json/app.js，12 页），用微信开发者工具导入该目录运行；appid 默认 `touristappid`（游客），正式发布需替换为真实 appid。
- **小程序主包瘦身（必做）**：`src/static/three`（H5 全景专用，小程序端用 npm 的 threejs-miniprogram）会被 uni 全量拷进主包白占 ~700KB。`build:mp-weixin` 已挂 `node scripts/strip-mp-static.js` 自动剔除，主包 2.12MB→1.50MB。勿删 src/static/three（H5 本地兜底需要）；勿改动该脚本（H5 构建不受影响）。
- **小程序 CSS 变量（必读）**：微信小程序 wxss **不支持 `:root` 选择器**（根选择器是 `page`）。`token.scss` 的变量必须挂在 `:root, page` 双选择器下；只挂 `:root` 时小程序端所有 `var(--primary/--success/--bg-card…)` 全部失效 → 页面颜色全丢（背景透明、文字默认色），表现"样式乱"。H5 靠 `:root`、小程序靠 `page`，两平台互不影响。改 token 定义后必须重建小程序并在开发者工具实测（模拟器页面圆点/标签背景等 var 色）。
- **小程序 SVG 图标（SIcon）竖排根因（必读）**：`<image>` 渲染无 width/height 的 SVG data-URI 时，微信小程序**按 SVG 固有尺寸（如 300×150）渲染，CSS width/height/max-width 全部无效** → 图标撑爆 flex 行 → 兄弟文本被逐字竖排挤出屏幕边缘（症状：文字竖排一列贴屏幕左/右缘、背景渐变只占窄条）。**修复**：SIcon 用 `<view>` + `background-image`（`background-size:contain`），view 的 width/height 在小程序 100% 生效。**排查口诀**：文本竖排 → 先查同行是否有 image 图标。
- **小程序验收铁律（必读）**：能编译、能打开 ≠ 渲染正确。必须逐页在模拟器**截图级验收**：OCR 检查关键文本是否横排（竖排时文字成窄列贴屏缘）、像素检查背景/渐变宽度是否塌缩。编译/切换页面后模拟器会重置到启动页；需登录的页面在游客模式只能验路由与门禁，实测需用户登录后补做，交付时必须如实披露未实测页面。
- **SCSS 规则误嵌套（样式静默全丢）**：`<style lang="scss">` 内前一块规则未闭合就直接连写下一块，会被编译成后代选择器（如 `.bind-hint .need-item{...}`），而 DOM 中两者平级 → 规则全不匹配 → 表现"点击没反应/无胶囊无高亮"。修复：前块先 `}` 闭合，后续规则独立平级。**排查口诀**：样式/交互"静默失效"→ 先查编译产物 CSS 选择器是否被误嵌套成后代。**交付前用"点击后像素/样式实测"验证**，不能只看源码逻辑在（供需标签踩过）。
- **跨端标签选择器失效（必读）**：uni-app 模板里 `<i>/ 月</i>` 这类 HTML 语义标签，H5 端保留 `<i>` 元素、`.price i` 选择器生效；**小程序端 `<i>` 被编译成无标签名的 `<view>`，`.price i` 标签选择器匹配不到** → 单位/后缀文字（/月、人）继承父级价格大字号加粗样式（44rpx/700/蓝），与 H5 不一致。**修复**：一律用 `<text class="price-unit">` + 类选择器，禁止依赖 `<i>`/`<b>`/`<small>` 标签选择器做样式（member.vue 套餐价格、visitors.vue 统计单位已踩）。**排查口诀**：H5 正常、小程序后缀文字变大有色 → 先查是否 `<i>` 标签选择器。

- **分包内模块相对路径（必读）**：`pages/card/utils/xxx.js` 被 `pages/card/*.vue` 引用时，路径是 **`./utils/xxx.js`**（同级 utils 子目录），不是 `../utils/`（那会解析到 src/pages/utils，不存在 → 构建报 "Could not resolve"）。已踩：cardOptions/cardTabState 移入分包时 sed 错两次。
- **小程序代码质量检测（性能合规）整改路径**：微信工具"代码质量"面板 4 类未过项的修法——①主包未使用 JS：仅被分包引用的模块 git mv 进分包（cardOptions/cardTabState → pages/card/utils/）；②JS/WXML/WXSS 压缩 + 组件按需注入：manifest.json mp-weixin.setting 开 `es6/postcss/minified/minifyWXSS/minifyWXML/lazyCodeLoading:"requiredComponents"`（构建后 project.config.json setting 必须回读确认）；③图片音频 >200K：SIcon PNG 用 gen-mp-sicons.js v2 只生成实际使用组合（1045→333 个、0.4M→120K）；④主包 <1.5M：strip-mp-static.js 剔除无引用 static（icons/images），zip 口径主包 0.50M、实际字节 1.14M。
