# 账号与权限规范

## 数据模型（accounts + tenant_members 分离）
- **accounts**：平台级登录账号（username/phone + password_hash/password_salt/status），一人一号，跨租户复用；不存明文密码。
- **tenant_members**：租户成员（tenant_id + account_id 关联），携带 name/nickname/status/identities(JSON)/enterprise_id 等租户侧属性；同一账号可加入多个租户。
- 登录入口：`POST /api/auth/login` 支持 `{username|phone, password}`，登录态返回 member_id。
- 权限模型：`roles`（内置 tenant_id=0 的租户管理员/普通成员/门店管理员 + 租户自定义）+ `member_roles` + `role_permissions`。

## 侧边栏菜单三处同步（必读）
侧边栏渲染源是 `web-admin/src/layouts/CustomerLayout.vue` 写死的 `<el-menu>`（不是 buildSidebarMenus）；改菜单必须三处同步：
1. CustomerLayout.vue（渲染）
2. menuPermissions.js（守卫）
3. menuPermissions.test.js（断言）
否则出现「路由能进、菜单不显示」或反之。

## 分配权限弹窗按应用分组
- **permission-tree 分组依据 = `app_menus.app_id` → `apps.id`，禁止用 `module` 匹配 app code**（module 是中文分组名不是应用 code）。
- **menu_key 含冒号前缀**（`card:overview`）；前端勾选标识 = `${app_code}:${menu_key}`；保存切分必须按第一个冒号 `k.indexOf(':')`，禁止 `k.split(':')`。
- 同名权限点靠分组归属区分，不拼接应用名到 label。

## 门店负责人 = 统一账号
- 创建/编辑门店负责人二选一（ownerMode）：new=新建账号（ownerName+ownerPhone+ownerPassword≥6位）；existing=复用本租户已有成员。
- 后端 resolveStoreOwner：新建自动 INSERT accounts+tenant_members+绑定 store_admin 角色；store 表仅存 owner_member_id。

## 成员/角色权限加固
- **最后管理员保护**：PUT /members/:id/roles 与 DELETE /members/:id 须保证至少保留1名 tenant_admin。
- **成员管理可授权**：新增权限点 `system:set-members`，有此权限的成员可进成员管理但角色管理仍仅租户管理员。
- **system 应用（hidden）**：apps 表 hidden=1 的系统级应用为权限点容器，不出现在应用中心但必须出现在分配权限弹窗。

## 我的账号
- 右上角个人中心 → /settings/account：个人信息+修改密码+我的角色与权限只读卡片。
- 与「成员与权限」分工：我的账号=个人自助；成员与权限=管理员治理全体成员。
