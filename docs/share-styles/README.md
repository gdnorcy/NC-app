# 个性化分享页 —— 落地方案

> 参考菜鸟云「个性化分享」页的**范式**（会话仿真预览 + 标题实时联动 + 封面风格库），
> 按 360全景 名片域重新设计。原型见 `prototype.html`，封面效果图见 `cover-1..6.png`。

---

## 一、为什么值得做这个页（而不是直接出一个分享图）

上一轮我出的 A/B/C/D 四张分享图，是**静态提案**——你挑一张、全平台统一用。问题在���：

| 静态统一图的问题 | 个性化分享页的解法 |
|---|---|
| 所有用户的转发卡片长得一样，没有辨识度 | 每人选自己的一版，姓名/职位/公司/电话按各自数据渲染 |
| 换风格要改代码发版 | 风格入库，选完即生效 |
| 用户看不到「转发出去到底长什么样」 | 顶部**微信会话仿真预览**，改一个字就能看到结果 |
| 配色写死 | 跟随租户品牌 5 色，未配置才回落 `#165DFF` |

**菜鸟云这个页最值得学的不是它的封面样式，而是「预览即所见」的结构。**

## 二、页面结构（与菜鸟云对齐）

```
┌─────────────────────────────────┐
│  ←        个性化分享        ⊙••  │  ← 品牌色导航栏
├─────────────────────────────────┤
│  ↓ 转发到微信后，对方看到的效果    │  ← 说明行
│  ┌───────────────────────────┐  │
│  │ (莞) 东莞市潮州商会    [我] │  │  ← 微信会话仿真
│  │ ┌───────────────────────┐ │  │
│  │ │ 点击保存对方名片   ›  │ │  │  ← 标题（实时联动）
│  │ │ ┌───────────────────┐ │ │  │
│  │ │ │   5:4 封面图      │ │ │  │  ← 5:4 硬比例
│  │ │ └───────────────────┘ │ │  │
│  │ │ (小) 名片             │ │  │  ← 小程序标识
│  │ └───────────────────────┘ │  │
│  └───────────────────────────┘  │
├─────────────────────────────────┤
│  修改分享标题 *            8/30  │  ← 计数 + 必填
│  [ 点击保存对方名片            ] │
│                                 │
│  选择分享封面      共 6 款·可滑动 │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐   │  ← 横向滚动
│  │ ▨  │ │ ▨  │ │ ✓  │ │ ▨  │   │  ← 选中=橙边+居中勾
│  └────┘ └────┘ └────┘ └────┘   │
│   品牌   名片   全幅   极简       │
│   渐变   卡     人像   白         │
├─────────────────────────────────┤
│           [ 保存 ]              │  ← 标题为空则置灰
└─────────────────────────────────┘
```

**交互要点**（已用无头浏览器实测 21/21 通过）：

- 改标题 → 预览区标题**实时变**；清空 → 预览显示「（未设置标题）」且保存置灰
- 纯空格也判定为空（`trim()`）—— 不能让用户存出一个空标题
- 点缩略图 → 预览图立即换、选中态唯一（橙色描边 + 居中橙色勾）
- 风格库横向滚动，`scroll-snap` 对齐到每项

## 三、6 款封面风格

| # | 名称 | 定位 | 适合谁 |
|---|---|---|---|
| 1 | **品牌渐变** | 品牌色铺满 + 底部触达条 | 默认款，最通用，字段少时最耐看 |
| 2 | **名片卡** | 白底 + 悬浮名片卡 + 底部 CTA | 商务正式，可打印 |
| 3 | **暗调商务** | 深色金边 + 细网格 | 高端/资深人士，宴会、论坛 |
| 4 | **全幅人像** | 人像为主 + 底部信息压条 | 有专业形象照的人，视觉冲击最强 |
| 5 | **极简白** | 大留白 + 左侧品牌竖条 | 字段极简（只有姓名公司），印刷友好 |
| 6 | **通知卡** | 「您收到一张新名片」+ 卡内名片 | 强调「刚收到一张新名片」的社交感 |

### 和菜鸟云封面的本质差异

菜鸟云的封面是**引流卡**——内容是「点击保存对方名片」这句广告。
我们的是**身份卡**——内容是**这个人是谁**（姓名/职位/公司/电话/城市/一句话）。

> 理由：转发到微信的是**熟人**，对方认识你，不需要广告语；需要的是「一眼看懂你是谁、怎么找你」。
> 真要有引导语，放在**分享标题**里（标题可编辑），比印在图上更灵活。

## 四、技术实现路径

### 4.1 微信的硬约束（决定了方案形态）

查证微信官方文档 `onShareAppMessage`：

| 字段 | 约束 |
|---|---|
| `imageUrl` | 可为**本地文件路径**、代码包文件路径、或网络图片；支持 PNG/JPG |
| `imageUrl` | **显示图片长宽比固定 5:4** |
| 返回值 | 支持 `promise`，3 秒内未 resolve 则用默认值 |
| `title` | 自定义转发标题 |

**关键结论**：`imageUrl` 支持本地临时文件路径 → **不需要服务端存图、不需要图片 CDN**。
封面在客户端用 canvas 按 5:4 画好，`canvasToTempFilePath` 拿到临时路径直接塞进 `imageUrl` 即可。

### 4.2 数据流

```
【个性化分享页】
  选风格 + 填标题
      ↓  PUT /api/card/cards/:id
  card_profile.share_style  ('cover-1'..'cover-6')
  card_profile.share_title  (≤30 字)
      ↓
【转发时】onShareAppMessage 返回 promise
      ↓  现场 canvas 绘制 5:4 封面（品牌色 + 真实姓名/职位/公司 + 真实小程序码）
  resolve({ title, path, imageUrl: 临时文件路径 })
```

### 4.3 需要改的地方

**① 数据库加两列**（`card_profile`）

```sql
ALTER TABLE card_profile ADD COLUMN share_style TEXT DEFAULT 'cover-1';
ALTER TABLE card_profile ADD COLUMN share_title TEXT DEFAULT '';
```

**② 服务端**（`server/src/routes/card.js`）

- `PUT /cards/:id` 的解构里加 `shareStyle` / `shareTitle`，UPDATE 语句里加两列
  （照现有 `voiceUrl !== undefined ? voiceUrl : card.voice_url` 的写法，避免未传时清空）
- `toCard()` 返回体里加 `shareStyle: row.share_style || 'cover-1'`、`shareTitle: row.share_title || ''`
- **注意**：`toCard` 是所有名片读接口的出口，改这里等于全端一次性拿到

**③ C 端新页面** `web-app/src/pages/card/shareStyle.vue`

- 顶部：微信会话仿真（预览区用 `image` 组件显示当前选中的封面）
- 中部：标题输入（带计数）、风格库横向滚动
- 底部：保存
- 入口：`myCard.vue` 的「分享」按钮旁加一个「个性化分享」，或长按分享

**④ 封面绘制**（新建 `web-app/src/utils/shareCover.js`）

把 `scripts/gen-share-covers.py` 的 6 款版式翻译成 canvas 绘制代码。
**这个文件必须两端通用**（MP + H5），所以：
- 画圆角矩形要自己写路径（`ctx.roundRect` 在部分基础库不支持）
- 渐变用 `ctx.createLinearGradient`
- 图片加载用 `canvas.createImage`（MP）/ `new Image`（H5）—— 照抄 `myCard.vue` 的 `loadImage`
- ⚠️ **`getCurrentInstance()` 必须在 setup 顶层取**（本项目已踩过，见 `myCard.vue` 的 `posterInst`）

**⑤ 转发接入**（`cardDetail.vue` / `cardMain/home.vue`）

把现在的：
```js
onShareAppMessage(() => {
  return {
    title: [...].join(' · '),
    path: `/pages/card/cardDetail?id=${id}`,
    imageUrl: /^https?:/.test(c.avatar || '') ? c.avatar : '',   // ← 生产库是 wxfile://，必然落空
  };
});
```
改成 promise 模式：
```js
onShareAppMessage(() => ({
  title: card.shareTitle || [c.name, c.position, c.company].filter(Boolean).join(' · '),
  path: `/pages/card/cardDetail?id=${c.id}`,
  promise: buildShareCover(c).then(url => ({ imageUrl: url })),  // 3 秒内 resolve
}));
```

### 4.4 两个必须提前解决的坑

**① 头像不是 https URL**

生产库 `card_profile.avatar` 存的是 **`wxfile://` 临时路径**（微信上传后的本地临时文件）。
- 转发封面画在 canvas 上没问题（canvas 能画 `wxfile://`）
- 但**分享给别人后，对方看到的是我们画好的成品图**，也不需要头像 URL
- ✅ 所以这不影响本方案。但要注意：**画进封面的头像必须是当前会话有效的 `wxfile://`**，若名片数据里的 avatar 是历史失效路径，需要在绘制前重新取。

**② 封面要自己画，不能直接用 `imageUrl` 传 `avatar`**

`avatar` 是**正方形**的，而微信要求 **5:4**。直接传会被裁。
必须用 canvas 画成 5:4（`W=750, H=600`）。

## 五、建议的推进顺序

1. **先做「单风格 + 全部字段可配」**（约 3 人日）：风格库只有 1 款，但标题/图/文案都能改。
   这一步就能验证「预览即所见」这个核心交互是否被用户接受。
2. **再加风格库**（约 3 人日）：把已验证的绘制代码参数化成 6 款。
3. **最后接转发链路**（约 1.5 人日）：`onShareAppMessage` 的 promise 模式。

> 理由：风格库是「量」的风险（画得不好看），预览交互是「质」的风险（用户买不买账）。
> 先验证后者，避免在 6 款封面上白花时间。
