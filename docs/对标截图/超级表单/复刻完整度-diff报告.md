# 超级表单 · 复刻完整度面板全文 Diff 报告（方法二）

> 验证方法：对 29 个组件，分别在 **ew 编辑器** 与 **我方编辑器** 中逐个点击组件库项、抓取右侧属性面板全文（ew 抓含「组件内容」的最大容器；我方抓 `.sf-props`），做 CJK 词块集合差分，揪出「无 label 的视觉块 / 缺失字段」。
> 证据归档：`28-ew-面板全文.json`、`29-mine-面板全文.json`、`30-diff报告.json`（均在 `docs/对标截图/超级表单/`）。

## 一、整体结论

- 对比组件：29 / 29
- 有差异组件：28（仅 `image` 在「内容设置」上与 ew 高度一致，差异仅来自我方多出的「上传-示例/未上传-示例」引导卡——该卡是按你贴的截图补的，ew 当前实例无此块，属**预期差异**）
- 原始 ewOnly 词块 188 个 / mineOnly 86 个；剔除结构性噪音后，真正的**功能缺失**集中在下方 B 类。

## 二、差异分类

### A. 系统性结构差异（最高优先级，影响全部装修/特殊组件）

ew 在**全部 29 个组件**上都渲染「是否显示（显示/隐藏）」+「是否必填（必填/非必填）」；我方用 `noPropTypes` 在 12 个组件上隐藏了这两项：

`pagebreak / backdesc / realtime / swiper / bigimage / title / richtext / blank / line / video / pay / submit`

→ 这 12 个组件的属性面板与 ew 外形不一致（少了顶部的显示/必填开关）。**若要做到 1:1，需放开这 12 个组件的「是否显示」，是否放开「是否必填」需你判断**（轮播图/标题等「必填」语义不成立，但 ew 确实展示了）。

### B. 真实功能缺失（ew 有、我方无该概念）

| 组件 | 缺失能力 | 说明 |
|---|---|---|
| checkbox | 排他选项（含「以上都不是」）、批量添加选项、添加「其他」选项 | 多选计数 min/max 已有（label 为「数量限制」差异），但排他/批量/其他选项缺失 |
| select | 预设类型（普通/省市区/日期）、下拉框级数（一级/二级/三级）、各级选项 | 我方是「选项类型（文字/图片/图文）」模型，与 ew 的「预设+级联」模型完全不同 |
| location | 内容类型：定位点 / 点到点（路线） | 我方仅单点定位，缺路线模式 |
| attachment | 上传类型（扩展名白名单：doc/xls/pdf/zip…）、大小限制 KB | 我方缺文件类型与大小限制（我方另加了只读/预填/校验作为超集） |
| agreement | 协议内容选择 + 显示方式（直接勾选 / 看完勾选） | 我方是「协议正文+链接」模型，缺 ew 的协议内容选择器与看完才勾选 |
| filedownload | 示例文件 + 提示文字 | 我方是「文件名称/文件地址+是否必填」模型，字段语义不同 |
| pagebreak | 禁止返回上一步、上一步/下一步按钮文字 | 缺分页按钮文案与禁止返回 |
| submit | 上下文提示（商品/活动/会员/文章/视频/音频表单下按钮功能说明）、跳转指定页面 | 缺场景化提示与跳转逻辑 |
| realtime | 虚拟人数、开启倒计时 | 缺假人数列与倒计时 |
| pay | 规格类型（单/多规格）、库存展示、支付退款、支付核销、支付限购、日期选择、优惠券、积分抵扣、会员折扣、支付分销 | ew 是完整电商支付；我方仅固定金额+添加规格+支付方式，缺退款/核销/限购/优惠券/积分/分销/会员折扣/库存展示 |
| swiper | 图片描述、选择图片/选择链接（picker） | 我方用图片地址+高度，缺描述字段（picker↔地址属模型差异） |
| bigimage | 选择图片/选择链接（picker） | 同上，picker↔地址差异 |
| title | 主标题文字、副标题文字、提示文字、标题链接 | 我方是文字大小/对齐/颜色/加粗（样式），缺文字内容与链接字段 |
| blank | 空白块高度 | 缺高度设置 |
| line | 线条高度 | 我方有线条样式/颜色（超集），缺高度 |
| video | 视频显示（直接显示/弹出显示）、自动播放 | 我方仅视频地址+封面图，缺显示方式与自动播放 |

### C. 我方独有 / 超集（安全，无需改）

- `number`：我方多出 提示文字 / 每次增减步进 / 默认值（ew 无）
- `text/textarea`：我方 readonly/校验 microcopy 措辞不同但功能等价
- `location/sms/attachment/rate/phoneauth/carplate`：我方多出 只读/预填/校验（ew 这些组件无该开关）
- `pagebreak/submit/pay`：我方多出 说明 文案

### D. 仅文案/标签差异（非功能缺口，按需对齐措辞）

- `text`：ew「开启只读则必填」↔ 我方「开启只读则仅显示」；ew「开启校验则相同内容无法重复提交」↔ 我方「相同内容不可重复提交」
- `text/textarea`：ew 用「输入限制」作为 min/max 输入的分组标题，我方直接平铺「最少输入/最多输入」
- `time`：ew「时间点」↔ 我方「单个时间」
- `backdesc`：ew「描述内容」↔ 我方「描述文字」
- `richtext`：ew「请输入正文」↔ 我方「内容」

## 三、修复优先级建议（待你确认范围）

1. **P0 系统性**：放开 12 个装修/特殊组件的「是否显示」开关（是否放开「是否必填」待定）。改动小、外形对齐收益最大。
2. **P1 高频基础组件**：checkbox 排他选项 + 批量/其他选项；select 预设类型+级联级数；location 路线模式；attachment 上传类型+大小。
3. **P2 支付/特殊**：pay 退款/核销/限购/优惠券/积分/分销/会员折扣/库存展示；realtime 虚拟人数+倒计时；submit 跳转+场景提示；pagebreak 按钮文案。
4. **P3 装修组件**：swiper/bigimage/title 文字+链接+描述；blank/line 高度；video 显示方式+自动播放；agreement 协议内容选择器；filedownload 示例文件模型。
5. **P4 措辞对齐**：D 类文案统一。

> 执行方式：每个组件改 `components.js` 默认值 + `SuperFormDesigner.vue` 面板 + `fill.vue` C 端逻辑/校验，并补 C 端无头验证（沿用之前 audit 的 19 测试 + 截图成对归档）。

## 四、本方法相较「无头截图抽查」的优势

- 抽取的是**面板渲染后的全文**，天然覆盖「无 label 的视觉块」（如你之前抽查发现的「上传-示例/未上传-示例」引导卡）。
- 29 组件一次性批量 diff，避免人工抽查遗漏。
- 输出可归档（`28/29/30-*.json`），可重复跑、可回归。
