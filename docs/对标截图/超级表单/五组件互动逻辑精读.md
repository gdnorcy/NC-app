## 一、下拉选择（select）

### 面板结构（内容设置）
```
组件属性：是否显示 / 是否必填 / 只读 / 内容校验
组件内容：
  内容标题：
  提示文字：
  预设类型：普通 | 省市区 | 日期(如需选择三级级数请直接使用日期组件)
  下拉框级数：一级 | 二级 | 三级        ← 仅预设类型=普通 时显示
  添加选项：编辑选项 | 批量添加        ← 仅普通 时显示
    tab：一级下拉选项 / 二级下拉选项 / 三级下拉选项（数量随级数变）
```

### 联动实测
- **预设类型 = 省市区 / 日期**：整个「添加选项」区消失（内置数据，无需配置选项）；级数行保留
- **预设类型 = 普通**：显示级数 + 选项区
- **下拉框级数**：默认 **三级**；选项区 tab 数量 = 级数（一级只有「一级下拉选项」）
- **编辑选项**：独立弹窗「编辑选项」，内含 tab（一级选项）+ 新增选项 + 取消/确定
- **批量添加**：弹窗「批量添加选项」（与 radio/checkbox 同款）

### 画布渲染
- 一级时是普通下拉（el-input + suffix 图标）；多级时用 **el-cascader**（级联单框）
- class：`widget-cascader widget-top-box1-cascader`（框）/ `widget-top-line-cascader`（线）
  - 左右布局时 `widget-left-*`：**两种风格都是透明无边框**（label 左置时输入框不画框）

### 风格 2 档 CSS（inline 变量）
```
--background-color / --border-color / --prompt-color / --enter-color / --icon-color
--border-top-left-radius / -right / -bottom-left / -bottom-right（4 个独立圆角）
```
```css
.widget-top-box1-cascader .el-input__inner { background: var(--background-color); border: 1px solid var(--border-color); border-radius: <4 圆角变量>; }
.widget-top-line-cascader .el-input__inner { background: transparent; border-top: 0; border-right: 0; border-left: 0; border-image: none; border-bottom: 1px solid var(--border-color); padding-left: 0; }
```

### 颜色 7 项
标题颜色 #000000 / 底框边框 #F5F2F2 / 底框背景 #F7F9FA / 提示文本 #CCCCCC /
选中文本 #333333 / 错误提示 #ED4F4F / **图标颜色 #000**

### ⚠️ 我方差距
1. 风格档：我方 s1/s2/s3 三档 → 对标站是 **box1/line 两档**
2. 设计器选项区：需按级数显示「一级/二级/三级下拉选项」分组（每级独立选项列表）
3. 「提示文字」字段需确认存在

### 🔬 源码级实测（2026-10-05 第二轮，反编译 app.e3bdd5d3.js `car-number-widget`）
用户指出车牌组件仍有差距后，从站点 JS bundle 反编译出组件完整源码与 scoped CSS（`data-v-6db10346`）：

```js
// render：8 个 el-input + 一个圆点 div
values.map((i, o) => el-input({
  class: ['card-normal-input', ..., o === values.length-1 ? 'card-normal-input_last' : ''],
  attrs: { disabled: '', placeholder: o === values.length-1 ? '新能源' : '' },
}))
t('div', { staticClass: 'point' })   // ← 截图里的「•」

// data：画布预填演示值
values: [{label:'苏'}, {label:''} × 7]
```

scoped CSS 关键规则（对照我方逐条复刻）：
```css
.card-normal-input { width: 12.5%; display: inline-block; margin-bottom: 10px; }
.card-normal-input .el-input__inner { width: 80%; margin-right: 10%; height: 49px;
  line-height: 49px; text-align: center; padding: 0;
  background: var(--bg-color); border: 1px solid var(--border-color);
  border-radius: var(--border-*-radius); }   /* 默认 #F7F9FA / #F5F2F2 / 3px */
/* 末格新能源位：固定绿色，!important，与所选配色无关 */
.card-normal-input:last-child .el-input__inner { border: 1px solid rgb(0,181,0) !important; color: rgb(0,181,0) !important; }
.card-normal-input:last-child .el-input__inner::-webkit-input-placeholder { color: rgb(0,181,0) !important; }
/* 圆点分隔符：4×4 圆形，left:23%（卡 2 右侧缝内），颜色 = 输入文字色 */
.point { width: 4px; height: 4px; background: var(--entertext-color); border-radius: 50%;
  position: absolute; left: 23%; top: 24.5px; }
```

**结论：格子是「独立圆角卡片 + 卡间留缝」，不是相连分格**；首格预填「苏」是画布演示值；
「•」是绝对定位的装饰圆点（非输入内容）；末格 = 新能源位（绿框绿字 + placeholder「新能源」）。
我方已于同日按此复刻（`.sf-plate` 独立卡片 + `.sf-plate-dot` + `.sf-plate-cell--ne`），C 端/预览端实测截图
见本目录 `verify-plate-C端.png` / `verify-plate-admin预览.png`。

### 🔧 用户追问：「新能源车牌」类型开关无效 / 概念不合理 → 取消开关，末格绿位设为可选（2026-10-05 第五轮）
**背景**：第三轮为解决「新能源三字挤 1 字格」落地了「普通/新能源一键切换」开关（`content.newEnergy`，关闭渲染 7 位）。
用户实际试用后指出两个问题：① 开关「无效」；② 概念不合理——「现在输入车牌都是不限车牌类型的，这样开关有意义吗？
我以为是在 C 端选择」。

**诊断（代码交叉验证）**：
- 技术上开关是联动的（`selected` 与画布 `comp` 同一响应式对象），能真的把预览 8 格↔7 格；
- 但它**不限制车牌类型**：C 端校验正则 `[省份][A-Z][A-Z0-9]{4,5}[末位]` 对 7 位和 8 位**都放行**、且与开关状态无关；
  所以开关只是「装饰性」改格数+末格绿框，没有承载「类型」语义 → 用户感知的「无效」；
- 更深层**概念错位**：车牌是「填表人那台车」的属性，**不是表单的属性**。让表单作者预先声明「本表单只收蓝牌/只收绿牌」
  选错了轴——同一表单大概率两种车都要收。**选择权应在填表人手里（即用户预期的「C 端选择」）**。

**最终方案（用户选定：方案 A）——取消类型开关，固定 8 格、末格绿位可选**：
- 移除 `content.newEnergy` 字段、设计器「新能源车牌」开关、面板该行；`defaultContent('carplate')` 去掉 `newEnergy`；
- C 端 / 预览端固定 `v-for="n in 8"`，末格恒为绿框「新能源」**可选**位：
  - 普通蓝牌（7 位）→ 填 7 格、**末格留空**（显示绿色「新能源」占位）；
  - 新能源绿牌（8 位）→ **填满 8 格**（占位消失）；
- 「类型」由 C 端填表人**填不填末格自然决定**（零配置、对标站做法）；校验正则在 7/8 位间自适应放行；
- 软键盘 `pressPlateKey` 末位固定为索引 7；`isPlateNePlaceholder` 内联为 `n === 8`。
- C 端实测：填 `粤B12345`(7 位) 末格留空显绿占位、再填末格 → `粤B123456`(8 位)，类型切换生效且校验均通过。

## 六、抓取方法论补充（本轮新踩坑）

1. **el-radio 用 JS dispatch 才能切**：真实鼠标 `mouse down/up` 在该站 el-radio 上不生效；
   `el.dispatchEvent(new MouseEvent('click',{bubbles:true,cancelable:true,view:window}))` 100% 生效。
2. `--profile Default --headed` 复用用户 Chrome 登录态；open 后如果还停在 about:blank，
   用 `agent-browser navigate <url>` 补一次导航。
3. 组件面板 tab 切换后引用失效 —— 每次 dispatch 前重新 query。
4. 左侧组件面板点击要点 `.field-widget-box__item`（外层容器），文字节点本身不响应。
5. 我方后台 3000 端口 = Express 托管构建产物（重启会掉登录态）；admin 改样式必须 vite build。
