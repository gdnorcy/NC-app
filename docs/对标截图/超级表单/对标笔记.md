### 基础设置 tab（2026-09-30 二次实测对标站修正）

### 逻辑设置 tab（05/06-*.png 初稿 → 19/20-*.png 2026-09-30 实测+读 ew 运行时源码确认）
- 说明文案（原文）："提示：请添加完所有组件之后再设置该逻辑部分（分页以及提交按钮不参与逻辑部分设置）。你可以为选择类字段（单项选择、多项选择、评分、下拉选择）设定规则，填写者选择某字段的某选项后，显示该字段之后的其他字段。操作文档：点击跳转"
- 字段白名单（读源码 conditions）：`radio / checkbox / rate / select`，与文案一致
- 规则结构：规则N（可折叠）=「当满足以下条件时」→ 条件行「在 [字段] [选项] 删除」+「添加条件」→ ⦿则显示字段 / ○则结束表单 → 显示：[多选，候选=触发字段之后的字段]
- 条件语义（读源码 changeWidgetelect）：
  - radio/checkbox → 比较符「选择了任一」（select_any），选项**多选**
  - select → 比较符「选择了」（equal），选项单选
  - rate → 比较符「介于」（between），两个下拉 最低~最高（1..最高量级）
- 多条件：条件行间出现「或/且」选择（rule.operator，默认 or；首行 el-select、其余行显示文本）
- 确定按钮校验（读源码 submitFieldRules）：
  - 重复条件 → "逻辑条件设置中存在相同项，请修改后再保存！"
  - 有「则结束表单」但表单无提交按钮 → "请确保DIY表单中存在提交按钮！"
- 底部按钮：+ 添加规则 / 确定 + "请点击确认按钮完成逻辑设置部分"
- 附：ew 的逻辑字段列表在**设计器加载时**快照（filterSelector 只在载入时调用），我们按画布实时计算（更优）

## 九、图片上传（picture-upload）内容设置：图片类型联动（ew 源码实测，2026-10-01 第七轮）
> 用户截图指出：图片类型（普通/身份证/营业执照）+ 示例图 没有复刻功能/逻辑/联动。

**面板结构（ew）**：组件属性（是否显示/是否必填）｜组件内容（内容标题/提示文字/**图片类型**/示例图/**输入限制：最少上传/最多上传**）
- 示例图：ew 内部键 `placeholderImg`，占位文案「示例图可引导用户上传规定模式的图片」
- 数量限制：ew 键 `insertLimit: {min, max}`，el-slider+show-input，**上限 10**，单位「张」；新建默认 `{min:null, max:null}`（面板显示 0/0）

**图片类型联动（ew `imgType-editor.handler` 源码逐字，含默认文案判断怪癖）**
```
idcard：  label 为空或「上传图片」→「上传身份证照片」；placeholder 为空 →「身份证照片仅用于实名认证」
          value={ward:'',back:''}；insertLimit.min=0 / max=0
license： label 为空或「上传图片」→「上传营业执照」；placeholder 为空 →「营业执照仅用于实名认证」
          insertLimit.min=0 / max=0；value=''
normal：  label 为空或「上传身份证照片」或「上传营业执照」→「上传图片」
          placeholder 为两条实名认证文案之一 → 清空；value=[]
```
- **注意 ew 怪癖**：idcard→license 时 label 仍是「上传身份证照片」（handler 只在 label 为空或等于「上传图片」时才改），复刻时按此逻辑照抄
- **面板联动**：示例图行 与 输入限制行 **仅 imgType==='normal' 时显示**（身份证/营业执照下隐藏，实测面板文本确认）
- imgType 枚举：`normal` / `idcard` / `license`（营业执照是 license，不是 business）

**C 端渲染（ew picture-upload-widget）**
- normal：上传框内显示 示例图（placeholderImg）+ 相机图标

## 十一、全量组件审计 + 隐性 bug 修复（2026-10-01 第九轮）

### 审计方法
逐组件比对三处一致性：① `web-admin/.../superForm/components.js` 的 `defaultContent`（默认字段）→ ② `SuperFormDesigner.vue` 面板 `v-model` 绑定字段 → ③ `web-app/.../superForm/fill.vue` 的渲染与 `validateList` 校验字段。共 29 个组件。

### 已修复的隐性 bug（均为「面板声明了、但 C 端/默认值没接上」）
1. **多选「最少/最多选择」字段名错配（高危）**
   - 旧：`defaultContent` 给 radio/checkbox 写 `min:0, max:0`，但 `validateList` 校验用的是 `ct.minSelect`/`ct.maxSelect`，`SuperFormDesigner` 面板也绑 `minSelect`/`maxSelect` → 多选的数量限制**永远不校验**。
   - 修：`radio` 仅保留 `options`；`checkbox` 改为 `minSelect:0, maxSelect:0`。校验/面板/默认三方一致。
2. **单行/多行文本「预填文字 + 只读」未实现**
   - 旧：`defaultContent` 有 `prefill`/`readonly`，面板也绑了，但 `fill.vue` 既不预填值、也不禁用输入 → 功能形同虚设。
   - 修：`load()` 中对 text/textarea 按 `prefill` 注入 `values[id]`；模板 `<input>/<textarea>` 加 `:disabled="comp.content.readonly"`（同时覆盖 number/date/time/carplate/select）。
3. **数字「间隔(step)」缺失默认 + 默认值不预填**
   - 旧：`defaultContent` 的 number 没有 `step`，面板有「间隔」；`validateList` 查 `ct.step` → step 校验永不触发。且面板「默认值」在 C 端不生效。
   - 修：number 补 `step:1`（默认不触发倍数校验）；`load()` 中按 `defaultValue` 预填数字；`step` 设为 2 等时即可正常校验「需为 N 的倍数」。

### 补齐的缺省字段（面板有绑定但默认未声明，避免 v-model 落到 undefined）
- `text`：补 `syncPhone:false`（面板有「同步手机号」）。
- `date`：补 `readonly/verifyRepeat/syncBirthday:false`、`defaultRange:[]`。
- `time/location/attachment/rate/phoneauth/sms`：补 `readonly:false`、`verifyRepeat:false`。
- 说明：`verifyRepeat`（相同内容不可重复提交）为后端去重标记，C 端仅存储，由服务端在提交时拦截。
