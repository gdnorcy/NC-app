# 微信参数与支付配置说明

> 对标菜鸟云「参数设置」的表单形态，但补上了它没有做的一件事：**数据库里不存明文密钥**。
> 2026-10-20

---

## 一、先回答一个常见疑问：为什么不都放 `.env`？

SaaS 和单租户系统的根本差别在这里：

| | 单租户（自己一个小程序） | 多租户 SaaS（本项目） |
|---|---|---|
| 小程序数量 | 1 个 | 每个租户自己 1 个 |
| 租户能否改配置 | 不能（开发者改） | **能，且必须能**（否则租户没法独立运营） |
| 配置放哪 | `.env` 够用 | **后台（租户填）**，`.env` 只作平台级兜底 |

所以本项目的分层是：

```
租户自己的 AppID / AppSecret / 代码上传私钥 / 商户号密钥  →  后台填写（落库加密）
平台自己的 AppID / AppSecret / 商户号密钥                 →  .env（永不入库）
```

**为什么密钥不能明文入库**：数据库会进备份、会被导出、租户管理员可能接触。
明文存 APIv3 密钥 + 商户私钥，等于把「能对任意商户号发起扣款」的凭据放在一个可能被多方读取的位置。
落库前用 AES-256-GCM 加密（主密钥 `STORAGE_KEY`），回显时脱敏成 `abcd****7890`。

## 二、后台要填什么

### 2.1 租户后台 → 全端渠道 → 微信小程序

对应菜鸟云截图的「参数设置」。

| 字段 | 存哪 | 必填 | 说明 |
|---|---|---|---|
| 小程序原始 id | `channel_apps.original_id` | 否 | 第三方平台模式用 |
| 小程序 AppId | `channel_apps.appid` | 是 | 已授权的由授权回调写入；自运营的在此填 |
| 小程序 AppSecret | `channel_apps.app_secret`（**密文**） | 自运营必填 | 微信公众平台 → 开发管理 → 开发设置 |
| 小程序代码上传密钥 | `channel_apps.upload_key`（**密文**） | 自运营上传必填 | 微信公众平台 → 开发管理 → 开发版本 → 小程序代码上传 |

> ⚠️ **代码上传密钥是 RSA 私钥**（就是你截图里那段 `-----BEGIN RSA PRIVATE KEY-----`）。
> 它的权限等价于「能往该小程序上传任意代码」，本项目已按最高敏感级处理：
> 落库加密、回显脱敏、只有租户管理员能写（`PUT /channels/:type` 带 `requireTenantAdmin`）。

**表单体验说明**：密钥字段回显为 `abcd****7890`。留空或保持占位符不变即表示「不修改」，
所以保存其它字段（品牌色、上传密钥等）不会误擦密钥。

### 2.2 租户/平台 → 支付配置

微信支付 API v3 需要这些：

| 字段 | 微信后台位置 | 必填 | 说明 |
|---|---|---|---|
| `mchId` 商户号 | 微信支付商户平台 → 账户中心 | 是 | 纯数字 |
| `appid` 收款小程序 | 与商户号**绑定**的小程序 AppID | 是 | 必须与 mchId 已绑定 |
| `apiV3Key` | 商户平台 → API 安全 → 设置 APIv3 密钥 | 是 | 32 位字符串，**设置后不可查看** |
| `privateKey` | 商户平台 → API 安全 → 申请证书下载的 `apiclient_key.pem` | 是 | 商户 API **私钥**（密文） |
| `cert` | 同上下载包里的 `apiclient_cert.pem` | 是 | 商户 API **证书**（密文），用于算 `serial_no` |
| `platformCert` | 商户平台 → API 安全 → 平台证书 | 建议 | **公开证书**，用于验回调签名 |
| `platformId` | 平台证书的序列号 | 建议 | 平台证书轮换时用于比对，防伪造 |
| `notifyUrl` 回调地址 | — | 是 | 见下 |

**回调地址必须填**：
```
https://你的域名/api/payment/notify/wechat
```
> ⚠️ 注意**只有一层 `/notify`**。本项目路由是 `POST /api/payment/notify/:channel`，
> 早期版本挂载路径重复导致实际路径变成 `/notify/notify/wechat`，
> 且 `/api/payment/notify/wechat` 会落到鉴权中间件返回 401 —— 已修复。

### 2.3 私钥的两种填法

| 方式 | 配置项 | 适用 |
|---|---|---|
| 贴 PEM 全文 | `privateKey` / `cert` | 简单，对齐菜鸟云表单 |
| 给文件路径 | `privateKeyPath` / `certPath` | 容器/密钥挂载，私钥不落库，更安全 |

两者填其一即可。

## 三、`.env` 里配什么（平台级兜底）

只有**平台自有**的凭据走这里，永远不进数据库：

```bash
# 平台小程序（所有租户共用一个 appid 时）
WX_APPID=wx0000000000000000
WX_APPSECRET=xxxxxxxx

# 平台自有商户号（作为「代收模式」的收款方）
WECHAT_PAY_MCH_ID=1900000000
WECHAT_PAY_API_V3_KEY=32位密钥
WECHAT_PAY_PRIVATE_KEY_PATH=/opt/app/secrets/apiclient_key.pem
WECHAT_PAY_CERT_PATH=/opt/app/secrets/apiclient_cert.pem
WECHAT_PAY_NOTIFY_URL=https://你的域名/api/payment/notify/wechat

# 密钥加密主密钥（**生产必须改默认值**，改了会导致已存的密钥无法解密）
STORAGE_KEY=<至少32字节的随机串>
```

> 🔴 `STORAGE_KEY` 一旦修改，数据库里所有已加密的密钥都会解不开（表现为登录失败、
> 支付签名报错）。请在首次部署时就固定下来并妥善备份。

## 四、接入后必须知道的四件事

### 4.1 openid 必须是真实的

JSAPI 支付的 `payer.openid` 必须由**真实小程序登录**产生。
本项目 `platform_user.openid` 目前库里是 `rebuild_openid_*` 之类的测试数据（清库重建时造的），
这些**不能用于真实支付**。

所以真实支付跑通的前提是：
1. 后台配好小程序 AppID + AppSecret（或走第三方授权）
2. 在真机小程序里登录一次，产生真实 openid
3. 未配置时 `app.js` 的 `wxLogin` 会回落 mock 通道（`openid='mock_xxx'`），
   此时下单会明确报错「未获取到付款人 openid」，**不会静默走 mock 假装成功**

### 4.2 mock 支付会自动关闭

一旦配置了真实商户号（`mchId` 不以 `MOCK` 开头），`POST /api/payment/mock-pay` 一律返回 **403**。
这是为了防止「知道订单号就能把订单标记成已支付」的漏洞。

### 4.3 回调验签失败会返回 401

`verifyCallback` 用**平台证书**验签（注意不是商户证书，方向相反）。
若返回 401，日志会有三种原因：

| reason | 含义 |
|---|---|
| `no_platform_cert` | 没配平台证书 |
| `platform_cert_serial_mismatch` | 平台证书轮换了，需更新 |
| `verify_failed` | 报文被篡改，或 `rawBody` 未正确捕获 |

### 4.4 金额单位统一是「分」

`payment_orders.amount`、`goods_order.pay_amount`、微信 `amount.total` 全是**分**。
建单时用 `price * 100` 或 `yuan2fen()`；**不要**在调用微信前再乘 100。

## 五、上线前自检清单

- [ ] `STORAGE_KEY` 已改为随机值（非默认值）
- [ ] 后台支付配置已填真实 `mchId` / `appid` / `apiV3Key` / 私钥 / 证书
- [ ] 商户号与小程序 AppID 已在微信后台绑定
- [ ] 回调地址 `https://域名/api/payment/notify/wechat` 可公网访问（须 HTTPS）
- [ ] 平台证书已配置（否则回调验签必失败）
- [ ] 真机小程序登录过一次（产生真实 openid）
- [ ] `curl -X POST https://域名/api/payment/mock-pay` 返回 403（确认 mock 已关）
- [ ] 用 0.01 元小额真实支付走通一次，确认订单变 `paid` 且权益已发放
