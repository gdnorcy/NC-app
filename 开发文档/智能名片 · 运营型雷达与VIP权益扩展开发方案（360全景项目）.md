# 智能名片 · 运营型雷达与VIP权益扩展开发方案（360全景项目）

# 方案概述

**核心判断：**在自研版（360全景项目，Node \+ Express \+ SQLite，服务工厂模式）上，把运营型雷达与 VIP 权益从“记录 \+ 开关”升级为“判断 \+ 转化 \+ 智能付费”。模块一在现有访客追踪（card\_visitor / card\_visitor\_action）上补事件、意向分、分级提醒、AI 话术、转发链与留资闭环；模块二在现有会员（member\_package / member\.js）上补龙兵四维（模板折扣 / 收藏上限 / 语音 / 建群数）并叠加 AI 能力、用量配额与企业席位三档付费。

本方案只描述设计与可照做的代码骨架，未改动任何现有代码；确认后再按阶段 A–D 实施。

# 模块一：运营型雷达

## 目标与市场对标

市场同类（宽脉、企晨、华为云、爱微商）雷达已从“谁看了我”进化到“判断 \+ 转化”：意向分、高潜排序、无感留资、AI 话术、CRM 同步。本模块以龙兵的事件推送为基线，叠加这五层能力。

|能力|龙兵 v8\.1\.9（参考）|本方案（自研版落地）|
|---|---|---|
|事件定义|radar\_event，事件启用才推送|card\_radar\_event，含 notice\_type 与重要级|
|意向判断|无（仅统计次数）|card\_radar\_intent 意向分 \+ 高潜排序|
|话术|radar\_words 按时间区间静态词|card\_radar\_words 静态兜底 \+ AI 个性化话术|
|推送|旧 formid 订阅消息（已废弃）\+ 公众号|一次性订阅消息 \+ 公众号模板|
|留资|无|对接 design\_leads 无感留资入池|
|转发链|无|card\_radar\_share 记录转发传播|

## 后端服务 services/radar\.js

新建工厂服务，仿 distribution\.js。核心方法：matchEvent（事件匹配）、computeIntent（意向分）、upsertClient（入客户池）、pickWords（话术）、sendNotify（推送）、trackShare（转发链）。

```js
export function createRadarService(db, deps) {
  const { payment, member } = deps || {};

  // 1. 匹配事件定义（按 actionType + tenant 命中 enabled 事件）
  function matchEvent(tenantId, actionType) {
    return db.prepare(
      'SELECT * FROM card_radar_event WHERE tenant_id=? AND name=? AND enabled=1'
    ).get(tenantId, actionType) || null;
  }

  // 2. 意向分：权重和 + 关键事件加成，归一化到 0-100
  function computeIntent(event, hitCount, durationSeconds) {
    let s = event.weight * 20;
    if (event.importance >= 2) s += 30;
    s += Math.min(hitCount * 5, 20);
    if (durationSeconds > 30) s += 10;
    return Math.max(0, Math.min(100, s));
  }

  // 3. 上报收口：记录行为后调用
  function onVisitorEvent(tenantId, ownerUserId, visitor, event, detail) {
    const now = Date.now();
    // 写意向分
    const prev = db.prepare(
      'SELECT * FROM card_radar_intent WHERE tenant_id=? AND owner_user_id=? AND (visitor_openid=? OR visitor_user_id=?)'
    ).get(tenantId, ownerUserId, visitor.openid || '', visitor.userId || 0);
    const hit = (prev ? prev.hit_count : 0) + 1;
    const score = computeIntent(event, hit, detail.duration || 0);
    if (prev) {
      db.prepare('UPDATE card_radar_intent SET score=?, hit_count=?, last_calc_at=datetime(\'now\') WHERE id=?')
        .run(score, hit, prev.id);
    } else {
      db.prepare('INSERT INTO card_radar_intent (tenant_id,owner_user_id,visitor_openid,visitor_user_id,score,hit_count) VALUES (?,?,?,?,?,?)')
        .run(tenantId, ownerUserId, visitor.openid || '', visitor.userId || 0, score, hit);
    }
    return { score, hit };
  }

  // 4. 高潜客户榜（P0）：按意向分降序
  function topLeads(tenantId, ownerUserId, limit = 20) {
    return db.prepare(
      'SELECT * FROM card_radar_intent WHERE tenant_id=? AND owner_user_id=? ORDER BY score DESC, hit_count DESC LIMIT ?'
    ).all(tenantId, ownerUserId, limit);
  }

  // 5. 话术（P1）：先按事件+命中次数取静态词，再可接 AI 生成
  function pickWords(tenantId, eventId, hitCount, profile) {
    const row = db.prepare(
      'SELECT words FROM card_radar_words WHERE tenant_id=? AND event_id=? AND time_start<=? AND (time_end=0 OR time_end>=?) ORDER BY time_start DESC'
    ).get(tenantId, eventId, hitCount, hitCount);
    if (row) return row.words;
    // AI 兜底占位：按 profile 生成一句话跟进建议（预留 AI 接口）
    return '该访客近期多次查看名片，可主动联系确认合作意向。';
  }

  // 6. 入客户池：复用 card_customer，source=radar，tags 追加
  function upsertClient(tenantId, ownerUserId, visitor, source) {
    const exist = db.prepare(
      'SELECT * FROM card_customer WHERE owner_user_id=? AND phone=?'
    ).get(ownerUserId, visitor.phone || '');
    if (exist) {
      const tags = JSON.parse(exist.tags || '[]');
      if (!tags.includes('radar')) tags.push('radar');
      db.prepare('UPDATE card_customer SET tags=?, updated_at=datetime(\'now\') WHERE id=?')
        .run(JSON.stringify(tags), exist.id);
      return exist;
    }
    return db.prepare(
      'INSERT INTO card_customer (owner_user_id,name,phone,wechat,company,tags,source,status,next_follow_at) VALUES (?,?,?,?,?,?,?,?,?)'
    ).run(ownerUserId, visitor.name || '游客', visitor.phone || '', visitor.wechat || '', visitor.company || '',
      JSON.stringify(['radar']), source || 'radar', 'pending', '');
  }

  // 7. 推送（P0/P1）：读 push_config，按 notice_type 分发
  function sendNotify(tenantId, ownerUserId, event, visitor) {
    const cfg = db.prepare('SELECT * FROM card_radar_push_config WHERE tenant_id=?').get(tenantId);
    if (!cfg || cfg.switch !== 1) return { ok: false, reason: 'no-config' };
    const openid = db.prepare('SELECT openid FROM platform_user WHERE id=?').get(ownerUserId);
    if (!openid) return { ok: false, reason: 'no-openid' };
    const payload = {
      openid: openid.openid,
      event: event.name,
      title: event.title,
      visitor: visitor.name || '匿名访客',
      time: new Date().toLocaleString('zh-CN')
    };
    // notice_type 1：一次性订阅消息（wx.requestSubscribeMessage 授权后推一次）
    // notice_type 2：公众号模板消息（需用户已关注）
    // 推送由外部 channel 封装，此处返回 payload 交由 routes 调用
    return { ok: true, payload, channel: event.notice_type };
  }

  return { matchEvent, onVisitorEvent, topLeads, pickWords, upsertClient, sendNotify, computeIntent };
}
```

## 事件匹配与意向分算法

在 /visitor/track 现有逻辑后追加：

1. 读取 actionType，调用 radar\.matchEvent 命中启用事件；未命中直接返回，不做额外处理。

2. 命中后按事件 importance 判断是否属高意向（转发 / 留电话 / 二次回访），高意向事件升级推送优先级与话术。

3. 调用 radar\.onVisitorEvent 累计 hit 并写意向分（权重 \+ 关键事件加成 \+ 时长），结果存 card\_radar\_intent。

4. 调用 radar\.upsertClient 把访客落入名片主客户池，source=radar、tags 追加 radar。

5. 调用 radar\.pickWords 取话术，写入 card\_customer\_follow 作为跟进建议（不自动群发，合规）。

6. 调用 radar\.sendNotify 推送名片主，channel 由 notice\_type 决定。

## 推送实现（关键差异）

龙兵使用已废弃的 formid（7 天过期）订阅消息；本方案改用新版微信**一次性订阅消息**：用户在名片页通过 wx\.requestSubscribeMessage 授权，每授权可推送一次，授权结果经 /radar/subscribe 上报后端留存，命中事件时消费一次授权推送。

公众号模板消息作为第二种通道：需名片主已关注公众号且有审核通过的模板，推送前在 sendNotify 内校验 gzh\_appid / gzh\_tmpid 非空，失败记日志不阻塞上报链路。

## 无感留资、转发追踪与 CRM 导出

- **无感留资（P0）**：名片页内嵌线索表单（复用 design\_leads），用户授权手机号即落线索 → 通过 upsertClient 进客户池 → 触发一次高意向事件与推送。

- **转发追踪（P1）**：分享名片时带 share\_url，被转发者打开记录 card\_radar\_share（from\_user\_id / to\_openid），名片主可见“谁转发给了谁”，二次传播视为高意向。

- **CRM 导出 / 企微同步（P1）**：/radar/export 提供 CSV 导出（客户 \+ 意向分 \+ 跟进状态）；企微同步预留接口位，待企微凭证联调。

## 集中校验服务 services/quota\.js

统一能力校验，避免权益逻辑散落各处；仿 distribution\.js 工厂模式。

```js
export function createQuotaService(db) {
  // 取用户当前会员等级与套餐（租户维度）
  function planOf(userId, tenantId) {
    const row = db.prepare(
      'SELECT member_level FROM platform_user WHERE id=? AND tenant_id=?'
    ).get(userId, tenantId);
    if (!row || !row.member_level || row.member_level === 'free') return null;
    return db.prepare('SELECT * FROM member_package WHERE level=?').get(row.member_level) || null;
  }

  // 校验某能力点是否可用
  function hasFeature(userId, tenantId, feature) {
    const plan = planOf(userId, tenantId);
    if (!plan) return false;
    return (JSON.parse(plan.features || '[]')).includes(feature);
  }

  // 用量配额校验：返回剩余额度（阶段B对齐：套餐有效期累计 + 成功才扣 + 超限引导升级）
  function quotaLeft(userId, tenantId, kind) {
    const pkg = planOf(userId, tenantId);
    let limit = 0; // 0 = 不限（free 无套餐不限；维持无感留资/收藏基础能力）
    let used = 0;
    if (kind === 'quota_lead') {         // 留资配额：套餐列 lead_quota
      limit = pkg ? Number(pkg.lead_quota ?? 0) : 0;
      used = db.prepare('SELECT COUNT(*) c FROM card_lead WHERE owner_user_id=?').get(userId).c; // 成功留资才计入
    } else if (kind === 'quota_push') {  // 推送配额：套餐列 push_quota（阶段D联调消费）
      limit = pkg ? Number(pkg.push_quota ?? 0) : 0;
      used = db.prepare("SELECT COUNT(*) c FROM card_radar_notify WHERE owner_user_id=? AND channel IN (1,2) AND status='sent'").get(userId).c;
    }
    return limit === 0 ? { unlimited: true } : { unlimited: false, left: Math.max(0, limit - used), used, limit };
  }

  // 收藏上限
  function canCollect(userId, tenantId) {
    const plan = planOf(userId, tenantId);
    const limit = plan ? plan.collect_limit : 0; // 0 = 不限
    if (limit === 0) return true;
    const used = db.prepare('SELECT COUNT(*) c FROM card_collect WHERE user_id=?').get(userId).c;
    return used < limit;
  }

  return { planOf, hasFeature, quotaLeft, canCollect };
}
```

## 修订一：tenant_id 反查缺失（重大，必须修）

**问题**：`platform_user` 表**没有 tenant_id 列**。租户归属记录在关联表 `tenant_individuals`（个人入驻）/ `tenant_enterprise_employees`（企业员工）中（参见 card.js `/user/profile` 的 JOIN 写法）。因此：

- 方案 `quota.js planOf` 的 `SELECT member_level FROM platform_user WHERE id=? AND tenant_id=?` 会报"无此列"；
- `/visitor/track` 是匿名接口（无 auth / 无 requireTenant），请求里拿不到 tenantId，方案的 `onVisitorEvent(tenantId, ...)` 没有数据来源。

**修订**：

1. radar.js 新增租户解析方法，上报链路先反查再入库：

```js
// cardId → card_profile.user_id → tenant 关联表 → tenant_id
function resolveTenant(cardId) {
  const card = db.prepare('SELECT user_id FROM card_profile WHERE id=?').get(cardId);
  if (!card) return 0;
  const row = db.prepare(
    `SELECT COALESCE(
       (SELECT customer_id FROM tenant_individuals WHERE user_id=? LIMIT 1),
       (SELECT customer_id FROM tenant_enterprise_employees WHERE user_id=? LIMIT 1),
       0) AS tid`
  ).get(card.user_id, card.user_id);
  return row?.tid || 0;
}
```

2. `/visitor/track` 改造顺序：`resolveTenant(cardId)` → `matchEvent` → `onVisitorEvent` → `upsertClient` → `pickWords` → `sendNotify`。

3. quota.js `planOf` 去掉 tenant 条件（member_level 就在 platform_user 行内），或改为按关联表查租户后再取套餐：

```js
function planOf(userId) {
  const row = db.prepare('SELECT member_level, member_expire_at FROM platform_user WHERE id=?').get(userId);
  if (!row || !row.member_level || row.member_level === 'free') return null;
  return db.prepare('SELECT * FROM member_package WHERE level=?').get(row.member_level) || null;
}
```

## 修订二：留资数据表用错（重大，必须修）

**问题**：`design_leads` 是**表单定义表**（tenant_id / page_type / form_title / fields），不是线索提交数据表，**没有 user_id 列**。方案的 `quotaLeft` 用 `SELECT COUNT(*) FROM design_leads WHERE user_id=?` 会报"无此列"。

**修订**：新建留资提交表，配额与无感留资都挂它：

```sql
CREATE TABLE IF NOT EXISTS card_lead (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id INTEGER NOT NULL DEFAULT 0,
  card_id INTEGER NOT NULL DEFAULT 0,     -- 来自哪张名片
  owner_user_id INTEGER NOT NULL DEFAULT 0, -- 名片主

  name TEXT NOT NULL DEFAULT '',
```

`quotaLeft` 改查本表：

```js
const used = db.prepare('SELECT COUNT(*) c FROM card_lead WHERE owner_user_id=?').get(userId).c;
```
